# Decisions — 1.200.0-rc1

## D-001：正式讨论前增加持久化准备阶段

- 状态：Accepted
- 原因：用户需要先细化议题、确认框架和组队，不能在 Enter 后立即让专家开讲。
- 约束：旧会话解码与既有 opening/discussing 流程保持兼容。

## D-002：正文流式与结构化分析分成两次模型任务

- 状态：Accepted
- 原因：当前结构化输出存在工具参数中，解析半截 JSON 不可靠；正文自由文本可稳定流式。
- 约束：结构化分析失败不得丢失正文，必须有安全降级。

## D-003：专家人数限制为 2～6

- 状态：Accepted
- 原因：兼顾观点多样性、等待时间与模型费用；默认推荐 3～4 位。

## D-004：扩展专家但保留已有 raw value

- 状态：Accepted
- 原因：确保已持久化的旧圆桌会话仍能解码。
- 结果：新增法律合规、数据研究、市场增长、组织运营；既有心理专家升级展示定位。

## D-005：流式正文结束与 OSR 分析显式分态

- 状态：Accepted
- 原因：正文已经生成完毕时继续显示闪烁光标会误导用户。
- 结果：草稿结束后界面切换为「整理立场」，正文保持可见但不再显示流式光标；结构化分析完成后原位替换为正式可引用消息。

## D-006：专家上限严格拒绝，不做静默截断

- 状态：Accepted
- 原因：用户必须明确知道并控制进入讨论的专家阵容，传入 7 位时悄悄截成 6 位会破坏该契约。
- 结果：确认接口先去重、保持顺序，再严格校验 2～6；同时要求当前阶段必须为 `.selectingExperts`。
