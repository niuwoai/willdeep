# Agent Runtime Kernel

WillDeep 1.315.0-rc15 把长生命周期 Agent 的宿主职责拆成两层：

- 宿主 Runtime 是内核：接收事件、校验信任、限流、去重、持久化，并决定何时唤醒或打断模型。
- 主 Agent 是 `init/systemd + 调度器`：在安全边界内理解事件、协调 Worker、终端、后台任务与外部连接器，并把结果交付给用户。

模型不直接拥有进程调度权。它只能看到宿主已经裁决过、大小受限的事件通知。

## 事件信封

`AgentKernelEvent` 是统一信封，包含目标会话、来源/类型、优先级、中断策略、调度权限、正文信任等级、用户/模型 audience、去重键、待用户操作标记和生命周期时间戳。调度权限与正文可信度是两条独立轴：宿主可以允许终端完成事件唤醒模型，但终端输出仍按不可信数据处理。

事件按会话写入带 schema 版本的 `agent-events/<session-id>.json`，App 重启后仍可继续投递。相同瞬时信号可在 5 秒窗口内合并；Relay 事件使用日志周期幂等键，即便服务端在 ACK 前重复投递，也不会再次启动模型。每会话最多保留 200 条、全局最多 1000 条，优先淘汰已处理及低优先级事件。

## 三档中断

| 策略 | 行为 | 典型来源 |
| --- | --- | --- |
| enqueue | 只入队，等待其他原因启动下一轮 | 文件变化、仅供用户查看的定时记录、审批投影 |
| yield-at-boundary | 当前模型或工具步骤结束后投递；会话空闲时立即唤醒 | Worker、终端、任务、媒体、工作流、外部消息 |
| preempt | 取消当前 provider 步骤，再从保留的 transcript 继续 | 仅宿主签发的 critical 事件 |

不可信或仅通过传输认证的外部事件，即使自称 critical/preempt，也会被强制降为 yield-at-boundary。Relay Token 只证明传输通道获准，不证明事件正文可信。

## 已接入的信号源

- Worker 完成或失败；
- 后台终端命令完成、终端退出；
- 后台 Job、媒体任务与 Workflow 完成或失败；
- 工具审批、危险确认、问答、补丁与 Plan 审阅；
- 定时任务触发；
- Collaboration Relay 的 Webhook、消息和邮件类事件；
- 宿主通过 `publishHostAgentEvent` 注入的可信系统事件，以及其他适配器通过 `AgentExternalEventIngress` 注入的受限外部事件。

审批只投影到 user interrupt lane，原审批对象仍是唯一决策源。旧版 Job、媒体和 Worker 完成队列暂时保留为恢复兼容层；Runtime 以资源 ID 检测已经进入内核的事件，避免同一结果向模型投递两次。

## 外部事件路由

在“设置 → 连接器 → Runtime 事件路由”中配置：

1. 启用至少一个连接器及其 Cloud Relay；
2. 填写 HTTPS Relay 地址（本机调试允许 `http://127.0.0.1`）；
3. 把 Relay 访问 Token 保存到 macOS 钥匙串；
4. 开启“轮询接收 Relay 事件”。

收到第一条事件时，宿主创建一个不抢占当前界面的“事件调度中心”后台会话。消息或邮件类事件会同时进入 Dock 待处理数字徽标；普通 Webhook 可以自动驱动主 Agent，但不会无端给用户挂红点。

桌面端只接受 `collab-relay.v2`：Relay 先把事件写入本地持久化日志；Mac 将事件写进 Runtime 日志并刷盘后才调用 `/events/ack`。若任一进程在 ACK 前崩溃，Relay 会重投，桌面端以事件 ID 去重。设置页会显示连接状态、最近成功时间、接收/ACK/积压计数与最近错误。

轮询失败使用 2–30 秒指数退避。认证外部事件每个会话 5 分钟最多主动唤醒 6 次，超额事件继续安全排队；未认证事件只能排队。外部正文会限制长度、限制 metadata 数量、净化模型控制标记，并转义 Runtime 自己的 XML frame；正文只作为数据交给主 Agent，不能授予工具权限或绕过审批。

## 用户界面

任务监控右栏新增“事件中心”，展示来源、优先级、时间、合并次数和是否需要操作。普通待处理事件可忽略；审批类事件必须回到原会话卡片处理，不能靠关闭事件行伪造“已批准”。

Dock 数字徽标统计原有主 Agent / Worker 工具审批、补丁和 Plan 请求，以及事件内核中非审批来源且 `requiresUserAction` 为真的事件。审批投影不会与原审批记录重复计数。

## 恢复与边界

- 投递给模型前先获得 lease；只有 provider 成功完成包含该事件的请求后才标记 handled。进程在中途退出时，未完成 lease 会在重启后回到 pending。
- “已由模型处理”和“仍待用户操作”是独立状态；模型读过邮件不等于替用户确认或回复。
- 已确认或已忽略事件只保留为近期审计记录；会话归档或删除后同步删除其事件日志与外部唤醒预算。
- 会话归档后不再自动唤醒；重新取消归档也不会恢复已清理的外部正文。
- hard preempt 只取消当前 provider task，不删除 transcript、工具记录或事件日志。
- Event Center 不是权限中心。终端、文件、浏览器和 MCP 仍经过各自原有的确定性授权路径。
