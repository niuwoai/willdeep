# 多专家会诊

> 对应版本：1.142.0-rc2

## 目标

多专家会诊用于把一个需要交叉验证的议题交给多个本机编码代理审阅，同时保留 WillDeep 作为主持人与最终责任主体。它不是“多数投票器”：最终结论优先采用仓库证据，并明确保留仍无法消解的不确定性。

## 启动方式

1. 在 Agent Composer 中先输入要讨论的议题。
2. 点击输入框底部的听诊器图标。
3. 选择“结构化会诊”或“圆桌群聊”。
4. 在配置面板中可继续修改会诊议题；勾选至少两位已安装专家，可从建议菜单选择模型 ID，也可手动填写；Cursor Agent 会尝试读取本机 CLI 当前模型列表，失败时回退内置建议；留空使用对应 CLI 默认模型。
5. 群聊模式额外选择 2–5 轮，然后点击“开始群聊”。

## 结构化会诊流程

1. 用户在 Composer 输入议题并打开“多专家会诊”。
2. 用户确认或修改议题，并从已安装的 Claude Code、Codex CLI、Cursor Agent 中选择至少两位专家；每位专家都可从建议菜单选择模型 ID 或手动填写，留空时使用对应 CLI 的默认模型。
3. WillDeep 使用当前会话模型生成初版方案。
4. 所选专家并行、相互隔离地完成第一轮独立评审。
5. WillDeep 汇总共识、分歧和证据缺口，形成阶段性归纳。
6. 每位首轮成功的专家收到全部首轮意见与阶段性归纳，并行完成第二轮互评。
7. WillDeep 读取初版、两轮意见与阶段性归纳，输出最终结论。

## 圆桌群聊流程

1. WillDeep 主持开场，明确议题、初步方案和需要专家回答的问题。
2. 专家按界面顺序逐个发言。每次调用都会携带此前完整公共聊天记录，因此后发言者可以直接回应前面的具体观点。
3. 每轮结束后，WillDeep 归纳已经解决的问题、仍有分歧的证据和下一轮必须回答的问题。
4. 重复用户配置的 2–5 轮；单个专家临时失败会显示错误，下一轮仍会再次尝试。
5. WillDeep 读取完整群聊记录并形成最终结论。

## 权限与安全边界

- Claude Code 和 Codex CLI 固定使用 `plan`；Cursor Agent 固定使用 `ask`。
- 外部工具上下文使用只读沙箱，不允许会诊自动改写仓库。
- 议题、初版和专家意见被封装成惰性数据区；提示词明确要求把区内指令视为数据。
- 单个数据区最多保留 12,000 字符，共享评审包最多 42,000 字符，避免无限扩张上下文。
- 单位专家失败不会立即终止会诊；只要首轮仍有可用意见，WillDeep 会继续归纳并在卡片中展示失败原因。若全部首轮专家失败，会诊才整体失败。
- 同一 App 同时只运行一场会诊，避免多个外部 CLI 争抢资源或混淆停止操作。

## 会话与中断

会诊以专用 `WorkflowReport` 存入聊天记录，保存议题、模式、阶段、所选模型、结构化评审意见或群聊消息、失败原因与最终结论。用户可以随时停止。若 App 在会诊中退出，重新打开历史会话时该会诊会恢复为“已取消”，而不是继续显示无法结束的运行状态。

## 当前边界

- MVP 仅支持本机已安装并可直接调用的 Claude Code、Codex CLI 与 Cursor Agent。
- 圆桌群聊采用可控轮次和轮流发言，不是无限持续的开放聊天室；这样每位专家都能看到完整上下文，同时控制调用成本和讨论长度。
- 会诊只产出分析与建议。若用户决定实施最终方案，需要在会诊结束后另行发起正常编码任务。
