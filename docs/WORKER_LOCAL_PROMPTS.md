# Worker：三档模型与五类职责

> 当前实现：1.312.0-rc2（2026-08-31）。

## 配置与职责

模型档位集中保存在 `AgentProfileStore` 的独立配置项中，仅保存提供商 UUID、模型 ID 和上下文预算，不保存密钥或职责指令。

| 档位 | 初始模型入口 | 默认上下文预算 |
| --- | --- | --- |
| 基础 standard | someim-32b（单一基础入口，无工种后缀） | 128K |
| 进阶 advanced | deepseek-v4-flash | 256K |
| 专家 expert | gpt-5.6-sol | 256K |

这些是可编辑的客户端默认配置，不是模型可用性、实际窗口或性能的测试结论。用户可从提供商已有模型列表选择 V4 Pro、Opus/Fable 等真实可用模型，不能把改名当成升级模型能力。

设置页默认显示五类公开职责：调查（generalist）、实现（implementer）、验证（tester）、审查（reviewer）、运维（ops_runner）。默认分别使用基础、进阶、基础、专家、进阶档；职责决定本地指令、工具、写入边界及轮数，模型档位独立选择。旧专用 ID 保留原工具契约供历史、Workflow 和内部窄任务调用；“显示旧工种兼容配置”可查看和编辑旧配置，不删除或合并用户指令。外部 CLI/调度执行配置仍独立。

`spawn_agent.worker_tier` 可选择 standard / advanced / expert。缺省沿用职责设置。无效/不可用档位拒绝执行；有独立模型绑定的旧工种或自定义工种不能被该参数覆盖。

## 路由与安全

- 模型单轮空响应按 1/2/4 秒最多重试三次（加首次共四次），不重建任务、不重复已完成的工具；主 Agent 和前后台 Worker 共用该规则。重试不占用额外 Worker 轮次，卡片显示重试计数，累计已报告的各次请求用量。部分有效输出、明确过滤/拒绝、鉴权错误和取消不自动重放；耗尽后仍明确报错，这不等于跨失败运行的持久化断点续跑。
- 未显式选择提供商时，默认模型只用于 some.im 会话；私有会话保留当前提供商，不因本机同时登录 some.im 而外发。
- 已选择的提供商 UUID 是精确绑定，失效时不选择另一个同类账号。默认档不可用会明确报告使用当前会话模型，且不自动升级；可在设置里配置私有模型档。
- 旧七个 some.im 托管工种别名在没有精确提供商绑定时映射到基础档；明确指定提供商的旧别名仅规范化模型名，不改变端点。其他明确模型、未知别名、私有提供商同名模型保留。
- 前台普通派发最多自动升级一次，进入相邻的已配置档位。验证失败、轮数耗尽、空报告或上下文溢出可触发；短但非空的答案不会因字数而升级。父模型不被假定更强，同一实际模型不会重复运行。
- 升级保留原工种 ID、完整指令、工具集合、写入要求、轮数、文件锁与单命令授权，不借用 deep 的工具集。取消继续传播；升级失败保留原报告并显示失败。
- 后台和 Workflow 继续沿用各自的单次执行/失败上报机制，不新增隐式付费重试。
- Runner 每轮请求前以模型支持窗口和配置预算的较小值计算输入上限，预留输出和估算余量。超限明确失败，不静默丢弃原始任务、安全指令或未闭合的工具调用。当前窗口来源包括已发现元数据与保守模型族估算，不承诺等同精确 tokenizer。
- 自动编码流水线按配置的基础档准入，保留宿主 verifier 与独立审查，不再按 someim-32b 字符串决定能否运行。

## 指令来源

`AgentSubagentJobPrompts.swift` 是工种职责与交付要求的唯一代码来源，通过 `capabilityPromptSection` 发送；`AgentProfile` 在基础职责后追加用户 soul 指令与技能。Runner 不因登录态、模型名称或旧 `hostedVirtualModel` 字段省略指令。该字段仅保留 Codable 兼容；工具与写路径安全边界始终由宿主执行。

## 命令审批修正

普通 `git diff -- internal/config/config.go .env.example deploy/k8s/configmap.yaml` 走静态只读白名单。精确模板名 .env.example / .env.sample / .env.template 仅在工作区规范路径内豁免凭据扫描；真实 .env、凭据目录、外部路径及解析后指向真实凭据的符号链接仍拦截。外部 diff/textconv、输出写文件等不属于普通只读白名单。

审批卡依据检查结果显示只读、可能访问敏感文件或待核对范围，不再把所有命令标成可能写文件。严格逐次确认模式仍尊重用户设置。

## 发布边界与后续

本轮只改 macOS 客户端代码，不修改生产网关、用户已保存的模型账号或 Rust/Android 客户端，不自动提交、发版或安装。

发布前需实际验证三个模型入口可用、没有工种 prompt 的 prepend/replace，并核验真实上下文、上游与费用。还需跨端适配后再退役服务端旧别名；压缩器和安全裁判是独立辅助能力，不能按前缀一刀切删除。历史网关稿 [SOMEIM_WORKER_VIRTUAL_MODELS.md](SOMEIM_WORKER_VIRTUAL_MODELS.md) 仅供兼容排查。

同档备用模型、跨档多次尝试的完整费用归集，以及真实任务的成功率/时延对比不属于本次已完成内容，后续需单独设计和验证。
