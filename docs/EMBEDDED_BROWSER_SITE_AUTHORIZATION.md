# 内置浏览器按网站授权

> 状态：1.399.0-rc1 起实施 · 取代 1.396.0-rc3 的“按工具授权”

## 背景

1.396.0-rc3 把浏览器的“一直允许”从整族（`browser:embedded`）收窄到单个工具，并让
`embedded_browser_eval` 每次都单独确认。结果是：一次普通的浏览任务里，打开网页、
点击、输入、执行脚本各要批一次，eval 每调用一次就问一次（实测百度任务连问 4 次）。

## 决策

1. **eval 不再逐次确认。** 内置浏览器的脚本运行在页面上下文里，读不到 httpOnly
   cookie；敏感登录态都在 httpOnly cookie 里，读到非 httpOnly 的 cookie 或
   localStorage 可以接受。eval 以用户身份发请求的风险与 click 同级，因此按普通浏览器
   工具对待。
2. **仍逐次确认的只剩两个：**
   - `chrome_debugger_command`：CDP 能读出包括 httpOnly 在内的全部 cookie；
   - `embedded_browser_upload_file`：把本地文件发给网站，每次都是单独的决定。
3. **“一直允许”按网站生效；“本会话允许”仍是整个内置浏览器**（只在当前会话有效、由用户
   明确点选，不再细分）。网站规则的签名形如
   `browser:embedded:site:www.baidu.com`：
   - navigate 用目标地址的域名；
   - 其余内置浏览器工具用**发起调用时**页面所在的域名。宿主在调用登记时把域名写进
     隐藏参数 `_willdeep_page_host`，模型传入的同名参数会被覆盖；
   - **执行时复核**：如果页面在批准后已经跳到了别的域名，调用直接失败，并要求模型重新
     发起，新调用再按新域名判定。这样一批里先跳到别的网站、再点击，不会借用旧网站的授权；
   - 空白页（没有域名）不产生网站授权，照常询问。
4. Chrome（`chrome_*`）暂不改：宿主拿不到 Chrome 当前标签页的同步地址，仍按单个工具授权。
5. **旧规则**：1.396.0-rc3 到 1.398 期间存下的按工具规则（`browser:embedded:embedded_browser_click` 等）
   继续匹配，不让用户重新批准；新批准一律存成按网站的规则。

## 不做的事

- 不对工具结果做按值脱敏，不新增声明式提取工具，不对 eval 脚本做静态分级：
  eval 放开之后，这些都属于不必要的复杂度。
- 不在网站授权内再识别“支付 / 发送 / 删除”这类有后果的点击，不拆分 Agent 与用户两套
  浏览器数据存储。需要时另行设计。
