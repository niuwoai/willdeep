# 第 1 章：快速开始与界面认识

[返回索引](README.md) · [下一章：工作区、会话与运行位置](02-workspaces-sessions.md)

## 1. 启动前准备

首次运行至少需要：

1. macOS 13.7 或更高版本。
2. 一个可用的 AI 模型来源：登录 some.im 托管服务，或在设置中配置自有 provider。
3. 一个准备交给 Agent 处理的本地目录；只聊天或咨询时也可以暂不选择。

如果通过源码运行，在 Xcode 中打开 `Xedit.xcodeproj` 后执行 `Command+R`。正式安装包直接从“应用程序”启动即可。

## 2. 认识 Agent 主窗口

主窗口可以拆成四块：

- 左侧栏：新聊天、自动化、工作区分组和历史会话。
- 中央区：当前对话、工具调用、计划、审批卡片与交付结果。
- 输入区：工作区、运行位置、执行器、模型、模式、审批、附件、插件和专家。
- 顶部与右侧：预览、Diff、文件、终端、媒体任务、网页组件、图片编辑等工作面板。

## 3. 创建第一个会话

1. 点击左侧“新聊天”，或按 `Command+N`。
2. 在输入区上方点击工作区名称，选择本地文件夹或已配置的远端环境。
3. 点击模型按钮，确认当前 provider 和模型。
4. 对小任务保持“普通”模式；复杂任务可切到“计划”。
5. 描述你要的结果、验收标准和不能触碰的边界。

一个好请求应尽量包含：

```text
目标：修复登录页在窄屏下按钮被遮挡的问题。
范围：只修改 web/src/login，不调整后端接口。
验收：yarn test 通过，并提供 390px 宽度的截图。
限制：不要提交、不要推送。
```

目标、范围、验收和限制写清楚后，Agent 更容易直接交付，而不是先表演一段“我十分理解您的需求”。

## 4. 一轮任务会发生什么

典型执行链路是：

1. Agent 读取工作区和规则文件。
2. 搜索相关文件、日志或页面。
3. 必要时形成计划并等待批准。
4. 调用工具执行修改、构建、测试或浏览器验证。
5. 遇到高风险操作时暂停并请求审批。
6. 在对话中总结结果、验证证据、剩余风险与交付物位置。

运行中可以继续发送补充要求；新消息会进入队列。若补充内容改变了任务目标，应明确写“替换上一条要求”，避免 Agent 把两套方向一起炖成一锅。

## 5. 如何写更有效的任务

- 指定结果，不只指定动作：写“生成可发布 PDF”，比“研究一下 PDF”更明确。
- 提供验收：构建命令、测试范围、截图尺寸、目标格式都可以是验收条件。
- 说清权限：是否允许安装依赖、修改配置、创建分支、提交和推送。
- 提醒敏感边界：生产库、密钥、客户数据、邮件发送和外部发布必须单独说明。
- 引用文件用 `@`，引用整个项目则先绑定工作区。

## 6. 完成后检查什么

- 最终回复是否明确说明“做了什么”和“如何验证”。
- Diff 中是否只有预期文件。
- 测试是否实际运行，而不是只建议你运行。
- 图片、报告和构建产物能否打开。
- 是否留下未解决风险、待人工确认或环境差异。
