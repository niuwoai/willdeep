# 第 2 章：工作区、会话与运行位置

[上一章：快速开始](01-quick-start.md) · [返回索引](README.md) · [下一章：模型、模式与审批](03-models-modes-approvals.md)

## 1. 工作区为什么重要

工作区限定了任务的默认上下文和文件操作边界。绑定后，WillDeep 会把会话、文件引用、Git 分支、终端、Diff 和交付物围绕该目录组织。

未绑定工作区时适合：

- 通用咨询、方案讨论和纯文本写作。
- 暂时不需要读取本地文件的任务。
- 在决定项目目录前先拆解需求。

绑定工作区后适合：

- 代码修改、测试、构建和 Git 检查。
- 文档、表格、图片和网站产物生成。
- 需要长期保留项目上下文的连续任务。

## 2. 选择本地工作区

1. 新建会话。
2. 点击输入框上方的“选择文件夹”或当前工作区名称。
3. 选择“选择文件夹…”。
4. 在系统目录选择器中选中项目根目录并点击“Open”。
5. 回到会话后确认输入区显示目录名和当前 Git 分支。

建议选择仓库根目录，不要直接选择整个用户主目录。目录越大并不代表 Agent 越聪明，只会让搜索像在仓库里找一颗指定颜色的螺丝。

## 3. 左侧工作区与会话分组

- 每个工作区下可以有多个会话。
- 一个会话应尽量对应一个清晰目标，例如“修复登录超时”或“生成发布说明”。
- 点击工作区标题可折叠或展开会话列表。
- 使用会话菜单可以重命名，建议用结果导向的标题。
- 左侧搜索按钮可以查找既有会话。

当侧栏收起时，窗口左边缘仍可显示最近会话入口。切换会话会恢复其工作区、侧栏和相关任务状态，避免把 A 项目的终端端口接到 B 项目上。

## 4. 本地与远端运行位置

工作区菜单旁的运行位置决定工具在哪里执行：

- 本地处理：在当前 Mac 的工作区中运行文件、Git、构建和终端操作。
- SSH runtime：通过 SSH 在远端主机中运行。
- daemon runtime：连接远端 `willdeep-agent` 服务。

选择远端运行环境时，应再次核对：

1. runtime 名称和主机是否正确。
2. 默认远端工作区路径是否存在。
3. 当前终端提示符和 `hostname` 是否匹配预期主机。
4. 任务是否允许写入、重启服务或访问生产数据。

## 5. Git 分支与隔离工作

输入区会显示当前分支。开始修改前建议：

- 先确认工作树是否已有他人或未完成改动。
- 大任务使用独立分支或 worktree。
- 不要默认允许 Agent 在 `main`/`develop` 直接提交。
- 提交和推送是独立授权，不应因为“允许修改代码”就自动推断。

若任务在独立 worktree 中执行，文件、分支和终端也应保持绑定到该 worktree。最终合并前再检查 Diff 和测试结果。

## 6. 会话队列与上下文

- 当前轮仍在执行时可以继续输入，消息会排队。
- 与当前目标无关的新需求最好新建会话。
- 长会话可压缩上下文，但历史记录仍应可读。
- 引用旧结论时，最好指出具体文件、消息或交付物，而不是只说“按刚才那个来”。

## 7. 推荐的会话拆分方式

- 一个 bug 一个会话。
- 一个可独立验收的功能一个会话。
- 研究、实现、发布若风险边界不同，可以拆成多个会话。
- 自动化任务使用专门会话，避免与人工临时指令混在一起。
