## 完成协议

1. **冻结目标合同**：绑定原始目标、验收项 ID/文本、验收类型与证据要求、逻辑项目、授权工作区及已批准约束。改变实质目标要产生新合同，不能只沿用旧 done；不由复核模型自行降级 UI 等证据要求。
2. **汇总实际产物**：从宿主交付日志构造 manifest，包含各任务、工作区身份、产物 revision/tree、最终集成 revision 和验证回执。节点报告只是线索，不是证据。相同仓库的多个工作树需要按真实仓库归属归并，不能简单按 UI 路径视为互不相干。
3. **先做确定性检查**：存在未交付节点、缺回执、身份不一致、过期合同或版本不匹配时，不花复核模型费用；明确返回可由 Agent 补齐的缺项。不自动扩大工作区或读取无关用户文件。
4. **验证最终组合**：在每个工作区的最终不可变集成版本上，复验受后续修改影响的检查。跨服务/UI 目标还需要组合后的接口或交互证据；各服务分别构建成功不是端到端通过。
5. **按验收项裁决**：将真实宿主证据与冻结要求对应，逐项记录通过/不足/失败。所有 required 项有有效证据后才允许父 Goal 完成；单个节点 merged 不触发整体完成。
6. **发布前再核对**：检查合同、manifest、最终 revisions、执行租约及取消状态仍相同。旧复核晚到、用户追加目标、最后一个节点又产生修改时，不允许旧结果结束新目标。

## 尽量少打扰用户

- 普通测试失败、依赖问题、临时网络故障、缺失日志及证据过期，进入自动补证/修复，不创建用户审核卡。
- 缺失证据只调度拥有该产物的节点，不重跑整个项目；原有通过项在输入和合同不变时可以复用。
- 相同命令、同一最终版本、同一环境只验证一次；复用必须以宿主回执及输入指纹为依据，不能仅比较命令字符串。
- 所有自动修复、辅助复核与命令仍共用父 Goal 的费用、时间、工具和取消边界。到期是预算停止，不应冒充权限拒绝。
- 只有实质产品选择、凭据/私有交互或新增不可逆权限需要用户。提问前合并同一项目的相同问题，保留已有回答，不要求用户代跑 QA。
- 日常界面显示“整体校验中/正在补齐第 N 项证据”等状态，不把每次工具完成或暂时断线变成人工待办。

## 实施顺序

1. 先定义可持久化的父合同、产物 manifest 和验收回执，并测试失效规则。
2. 将最后一个节点交付后的宿主流程接入整体校验；保留节点进度，单独表达父 Goal 的验收状态。
3. 接入单仓库最终集成版本回归和增量缓存，再扩展多工作区组合验证。未支持的适配器明确保留未完成，不能降低验收要求。
4. 接入持久化恢复与按缺项自动返工；最后进行长跑、崩溃/重启和故障注入验收。

## 必须验证的真实场景

实现接线不能只停在新增结构体：`AgentDispatchCoordinator.project` 需要投影原始验收合同并保留仍有效的宿主整体验收状态；`deliverVerifiedDispatchTask` 最后一个节点交付后启动父校验；`resumeDispatchGoal` 必须能恢复“节点全交付、父校验未结束”，而不只寻找待运行节点。后台校验需要独立租约并接入暂停、Stop 和父预算。`AgentDispatchGoal.isComplete`、图上 acceptance gate、`AgentDispatchAcceptanceInspectorView` 以及持久化恢复需要共用这份状态。

- A 验收通过，B 后续修改使 A 回归失败：节点都交付仍不能结束父 Goal。
- 两个仓库分别通过，但跨仓库 API 不兼容：组合验收失败，自动定位并只修复相关节点。
- 第七条验收失败不得被截断；重复检查不能重复消耗或生成虚假更多证据。
- 等待复核时用户改目标、换工作区、Stop 或预算到期：旧结论不能发布完成。
- 发布回执前后崩溃：恢复后不重复副作用，也不把未落盘结果当已完成。
- 未变化根使用有效缓存，变化根重验；不能因一个无关文件变化重跑全部工作。
- 所有节点交付且整体验收通过：父 Goal 自动结束，不要求用户手动点击“认可完成”。

成功指标应同时记录端到端完成率、错误完成率、达到有效验收的时间、重复工作/复验成本、用户介入次数及原因。测试数量和模型自报完成率都不能代替这些指标。
