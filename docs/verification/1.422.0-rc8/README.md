# 1.422.0-rc8 / 930：统计保存 CPU 热点修复

## 现场证据

2026-10-21 通过 QTerm MCP 的既有 some.im 主机连接，使用只允许读取的查询工具检查 `client_perf_reports`。查询截止 UTC 04:43:46，近 48 小时新增 63 份 WillDeep 报告：rc7 有 25 份、rc5 有 18 份、rc4 有 14 份、1.421.0-rc2 有 6 份。当前 rc7 的报告 CPU 峰值最高 279.6%。历史版本分别统计，不把旧报告当作当前回归。

25 份 rc7 调用栈均与发布 dSYM 的 x86_64 UUID `4DF16326-6123-3906-B94F-9A0819D7A860` 匹配并完成符号化。多份报告显示 `AgentSessionStore.saveAsync` → `writeUsageCatalogEntryBestEffort` → `AgentUsageDatabase.upsert/writeSession`，同时仍可见侧车 JSON 编码、上下文估算和界面更新等其他工作。本次聚焦统计数据库反复重建历史的成本。

`PerformanceWatchdog` 等待自身采样进程的栈不计为业务 CPU 热点。采样数字是包含子调用的样本数，不能相加成为 CPU 占比。原始报告、安装标识、账号字段、用户内容和机器路径不随源码提交；脱敏聚合见 [profiles-summary.json](profiles-summary.json)。

## 实现

之前每次保存都会删除该会话的所有消息与工具行，再全量插入。现在仅在有可信的已提交基线时，更新会话元数据、变更的消息与工具行，并清除截断后的尾部；首次写入或缓存失效仍完整重建。

- 最多缓存 4 个会话，每会话最多 4096 条统计快照；不保存会话正文。
- `BEGIN IMMEDIATE` 内检查 SQLite `data_version`，其他连接的提交会使基线失效。
- 只有事务提交成功才更新基线；任一步失败回滚，清除基线供后续完整重试。
- 删除和整库替换清除基线。表结构、统计口径、原始会话保存及 JSON 侧车回退不变。

## 验证

专项覆盖历史字段修改、工具列表替换、追加、重排、截断、清空、跨连接写入、整库替换，以及增量事务中途失败后的完整回滚和重试。最终完整串行回归 5066 项通过、1 项跳过、0 失败，Xcode 退出码 0，计数一致。详见 [tests.json](tests.json)。首轮并发运行出现多组模拟 Provider 超时与共享状态失败，已停止并保留日志，不作为通过证据；产品代码未变后按既有串行入口完成复跑。
