# Mac 独立子会话：首次只读委派

> 状态：1.428.0-rc2 修正原生工具发现，2026-11-05 完整单测通过（5144 通过、2 跳过）。隔离 Debug App 使用本机 gemma4:e2b-it-qat 交互时，模型未调用原生 `start_session`；实机委派尚未验收通过

## 目标与边界

父会话调用常驻核心工具 `start_session(title, prompt)`，在同一个已授权的本地工作区启动完整的后台聊天。该工具默认可见；会话自动化工具包继续提供其他管理工具，短剧插件的同名工具属于插件命名空间。子会话不继承父会话的消息历史；调用方必须提供自包含简报。宿主绑定父会话和工具调用 ID，模型不能指定父会话、子会话或委派标识。父会话可以发起多条独立任务；子会话也能请求创建同级会话，宿主将新会话直接挂在原父会话下，不允许再建下一层。最多允许同一父会话同时存在四条未结束的首次委派。

首版固定只读：子会话可读取本地文件、目录、搜索结果与工作区会话概况，也可询问用户；命令、编辑、外部插件、跨会话发消息、Worker 和嵌套委派均不可用，唯一委派入口只创建同级只读会话。这里的只读限制在模型可见工具表和工具执行入口各检查一次；改变审批档位不会提高能力上限。外部编码执行器与自动 Worker 路由被禁用。此阶段没有可写 worktree，因此不接受需要修改代码、运行测试或部署的委派。

## 关系、状态与存储

`AgentSession.parentSessionID` 单独表达通用父子关系，不复用调度项目的 `dispatchParentProjectID` 和 `dispatchTaskID`。子会话的 `childSessionAssignment` 记录首次简报、状态、时间和有界结果摘要；旧会话解码时这两个字段均为空。完整记录保留在会话 JSON，目录侧车只保留短摘要，供侧栏与搜索快速加载；会话主文件、目录侧车和用量缓存（侧车及数据库）都对凭据形态的内容脱敏。删除或归档父会话不会级联删除子会话；父会话不可用时，子会话仍可独立打开。

启动时先创建独立的 `AgentRuntime`，同步确认委派关系已落盘（失败即清理空子会话并拒绝委派），再以宿主来源把简报送入子会话首轮。子会话等待人工输入或审批时记录为 `waiting`，答复后恢复 `running`；排队或供应商预备阶段的停止、失败、完成和重启中断均为首次委派终态。首次结果在自动上下文压缩与下一条排队消息之前落盘；其他待处理后台事件不能把后续回复替换成首轮报告。压缩失败或自动续跑额度耗尽时，子会话不使用会丢失只读边界的顶层接力，交接记录为 `interrupted` 并通知父会话。用户以后在子会话继续聊天不修改首次结果。App 重启时不会重放可能已经调用工具或计费的首轮：未结束的委派标记为 `interrupted`。

首次终态确认写入子会话记录后，才以稳定的通知 ID 和 journal 去重键写入原父会话的 `AgentRuntimeKernel`；写盘失败时暂缓通知，并在同一进程有限次数重试；仍失败则保留错误提示，下一次会话结算或 App 重启后补发。父会话通知的标题和结果正文也对凭据形态的内容脱敏。子会话发起同级任务时也由这个父会话接收结果。正文里的报告来自另一模型，标注为不可信的任务数据；父会话仍需核实后才据此行动。父会话忙碌时事件按原有内核节奏交付；父会话已归档或删除时不唤醒，子会话记录仍保留。

## 界面与验收

工作区侧栏按父子关系投影树行；折叠时每个可见父会话只预览有限数量的历史子会话，未结束子任务及其父会话始终可见。置顶和归档区保持各自的时间排序；过滤导致父会话不在同一区域时，子会话独立显示。结果摘要不是完整对话，点击仍打开子会话聊天。状态和操作文案使用 `SessionManagement.xcstrings`。必须验证旧数据兼容、目录侧车、空壳清理、树排序与孤儿保留、工具能力边界、等待与重启恢复、独立运行时的父会话通知。

后续阶段如需可写委派，必须先设计每个子会话的隔离 worktree、分支合并权限和冲突处理，并分别验收历史 fork、续做及跨机器交接。本阶段不承诺这些能力。
