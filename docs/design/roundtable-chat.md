# 主会话专家圆桌卡片

采用方案 3 的发言时间线，卡片承担实时预览和导航，完整讨论及所有用户交互由左侧菜单「专家圆桌」承担。

## 展示

- 标题行显示圆桌名称、阶段、轮次和实际已用时间；结束后计时冻结。
- 专家席沿用宿主现有头像，当前专家以橙色标记。
- 时间线保留最近三条专家发言。历史正文显示开头最多 220 字，并限制三行；截断时提示前往圆桌查看全文。
- 当前发言显示最新最多 1600 字，正文区域固定 140 点高度，流式更新时跟随末尾。保留姓名及发言状态。
- 需要答复时显示提示，唯一操作是「前往专家圆桌」，打开这张卡所对应的讨论。
- 主会话不提供插话、回复、继续或停止按钮。

## 工具与数据

`start_roundtable` 后台启动圆桌，立即返回会话标识。`get_roundtable_status` 读取阶段、最近公开正文和完成后的结果。启动成功不表示讨论完成；模型不得代替用户答复专家。

原生工具绑定准确的发起会话。现有插件反向调用没有发起标识，只在当前会话是唯一正在响应的会话时绑定，避免并发时猜测归属。卡片直接观察圆桌 runtime，不将每次正文增量写入主模型上下文。

## 验证

原生渲染测试覆盖数万字发言的高度约束，以及讨论中、等待答复两种卡片状态。时间线单测覆盖截断、切换专家、终态、错误和旧报告兼容性。参考图为 `roundtable-chat-reference.png`；实际原生渲染图为 `roundtable-chat-discussing.png` 和 `roundtable-chat-awaiting-user.png`。

## 设计核验

- 已检查 NSHostingView 实际渲染：标题、专家席、三条时间线及底部导航均无重叠；讨论中发言区域限高，等待答复状态显示橙色提示。
- 相比参考图，保留宿主现有专家头像和原生按钮样式；自定义专家使用现有首字头像。时间戳置于发言行右侧，以给长正文留出空间。
- 截断是字符与行数限制，不是模型生成的摘要；无需额外模型调用，也不会改变专家原文。
- 证据来自隔离的原生组件测试与路由契约检查，尚未在安装版中调用真实模型进行端到端试跑。
