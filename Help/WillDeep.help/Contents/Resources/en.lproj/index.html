WillDeep Help

Let the agent inspect the work, act, and leave evidence.

WillDeep is a native macOS agent workbench built around workspaces, sessions, and deliverables. It reads projects, drives the terminal and browser, edits files, runs tests, works on remote machines, and puts every change, tool output, and artifact back into the same session for review.

Getting started

  • You need a model source first: sign in to the some.im managed service, or configure your own provider in Settings > AI Providers.
  • Pick a workspace (a local folder) on the left side of the composer. It is the boundary for everything the agent reads, writes, and runs.
  • Type what you need and send. The agent reads files, runs commands, and edits code on its own, and stops to ask when something needs your approval.
  • Press Command-N for a new session. WillDeep is agent-only: general-purpose file editing lives in the standalone Qeditor app, so what you get here is read-only preview and diff review.

How the agent works

  • Every session owns its own runtime. Switching sessions never cancels a request in flight; other sessions keep running in the background and the full transcript is there when you return.
  • A turn goes: your message, context assembly (global rules, project rules, relevant memories), model output, tool calls, approval, execution, results fed back to the model, and repeat until a final answer.
  • Tool calls collapse into readable activity summaries (files read, commands run). Expand one to see the full arguments, output, errors, and where the approval came from.
  • Requests to the same provider queue up, three at a time by default and adjustable in Settings. Different providers do not block each other.
  • You can keep typing while the agent is busy — messages queue — and you can stop the current turn at any point.

Approvals and safety

  • The composer sets a per-session approval tier, from tightest to loosest: Strict mode, Smart review, Workspace write, Full access.
  • Decisions are deterministic first: a malicious-command blocklist stops everything in every tier, common read-only commands pass automatically, remembered grants apply, and only what is left may go to an AI judge.
  • Destructive operations always require you to type a confirmation. No tier auto-approves them.
  • Read-only commands run in a restricted environment with networking and out-of-scope writes disabled. Execution is written to an audit log in the app support directory with secrets redacted.
  • File edits arrive as a change summary and a diff you can review, apply, or reject.

Workspaces and run location

  • A session's workspace can be a local folder or a directory on a remote machine.
  • Add an SSH or daemon runtime in Settings > Runtimes, then pick the run location in the composer to execute tools remotely.
  • SSH stores only the path to your key file, never the private key itself. Daemon tokens live in the keychain.
  • Inside a Git repository you can create, switch, and prune worktrees straight from the composer's workspace menu.

Panels

  • The right-hand panels cover files, terminal, diff, web preview, media tasks, and image editing, all sharing the current session's workspace.
  • The terminal panel is a real terminal: what the agent runs and what you type see the same environment.
  • The diff panel lists this turn's changes per file so you can check them before applying.
  • The left sidebar groups past sessions by workspace. Right-click a group to remove it from the list; that only hides it, the session data stays.

Scheduled tasks

  • Scheduled in the sidebar is where WillDeep runs something on its own schedule: a morning brief, a weekly review, a project check.
  • Each task shows its schedule, workspace, and next fire time. Paused tasks say so instead of claiming a next run.
  • Hover a task card for Run now and Pause. Right-click to edit or delete.
  • Recent runs list the last few results with failure reasons, and link back to the session that ran them.

Plugins and extensions

  • WillDeep extends in four ways: skills (change how the AI works), MCP servers (give the AI new real capabilities), workflows (repeatable multi-step orchestration), and plugins (add a surface you operate directly, in the main navigation).
  • More Plugins opens the plugin center: install, enable, pin to navigation, check for updates, roll back a version, and uninstall. Permissions are listed before anything is written to disk.
  • Plugins shipped with the app include the classic arcade, Tetris, favorites, to-dos, session vitality, and project overview.
  • Plugin pages run isolated: no network, no file access, no keys. Anything real they do goes through a command declared in their manifest.
  • To build your own plugin, the full architecture and API documentation ships with the app at WillDeep.app/Contents/Resources/BundledSkills/willdeep-plugin-dev/. Start at SKILL.md; references/ covers runtime architecture, a quickstart, manifest fields, the page API, and packaging and security. Asking the agent "how do I write a WillDeep plugin" makes it read the same document.

Settings and command line

  • WillDeep > Settings covers providers, local agents, skills, rules, memory, notifications, appearance, and remote runtimes.
  • The Rules tab enables a global rules file (~/.willdeep/CLAUDE.md by default) that applies across projects. A project's own AGENTS.md or CLAUDE.md is more specific and wins.
  • Install the command line tool from Settings > Tools, then run willdeep-app . to open WillDeep on the current folder. It installs to ~/.local/bin; add that to your PATH if needed.
  • Appearance adjusts interface font, size, color style, and font smoothing.

Troubleshooting

A message seems to go nowhere.
Check whether the composer shows a queued state — requests to one provider queue up. If you use the managed service, confirm you are still signed in.
The agent keeps asking about the same kind of command.
Move the approval tier to Smart review or Workspace write, or choose to remember that command on the authorization card. Destructive operations always ask; that is by design.
A plugin page is blank.
Use the refresh button in the page toolbar. If it stays blank, check in the plugin center that the plugin is enabled and its minimum version is met; load failures now state the reason on the page itself.
I want to edit a file directly, but I cannot.
WillDeep is agent-only now; general-purpose editing belongs to the standalone Qeditor app. The file panel here is a read-only preview, and changes come from the agent for you to review in the diff.
Remote commands will not connect.
Re-probe that runtime in Settings > Runtimes. SSH uses the system ssh, so first confirm you can log in to the same host from a terminal without a password prompt.
