# 第 15 章 远端工作区：SSH 与 willdeep-agent

项目在服务器上、本机跑不动、或者要在生产机器上查问题——这些情况下，不用把代码拉回本机。WillDeep 可以把工作区放在远端，命令在那边执行，过程和结果仍然显示在你眼前。

配置在「设置 → 运行时 → 运行时」。

## 15.1 两种远端方式

| 方式 | 怎么连 | 适合 |
|---|---|---|
| **SSH** | 用系统的 `ssh` 客户端，BatchMode 认证 | 大多数场景，配置最简单 |
| **Daemon** | 通过 HTTP/WebSocket 连到远端跑着的 `willdeep-agent` | 需要更完整的远端能力、或者 SSH 受限的环境 |

## 15.2 配置一个 SSH 运行时

点"添加 SSH 运行时"，填这些：

| 字段 | 说明 |
|---|---|
| 显示名称 | 列表里看到的名字 |
| 传输方式 | SSH |
| 主机 | 域名，或者你 SSH config 里的 Host 别名 |
| 用户名 | 远端登录用户 |
| 端口 | 默认 22 |
| SSH 身份文件路径 | 可选，例如 `~/.ssh/id_rsa` |
| 远程工作区路径 | `/path/to/project` |

有一句话写在界面上，值得复述一遍：**WillDeep 只存储身份文件的路径，绝不会存储私钥内容**。认证走系统的 ssh 客户端，用 BatchMode——这意味着如果你的 key 带密码短语而又没加进 ssh-agent，连接会直接失败而不是卡在密码提示上。

推荐做法是先在 `~/.ssh/config` 里把主机配好（跳板机、端口、密钥都在那儿写），这里只填 Host 别名。

填完点"测试并探测"。成功之后它会告诉你远端的平台、能力、工具链、镜像源、代理设置。没装 GitHub CLI 的话会提示你去装并 `gh auth login`。

## 15.3 交互式终端的启动队列

远端终端不像本地那样开箱即用——你可能要先 `cd` 到某个目录、先 `source` 一个环境、或者还要再跳一层堡垒机。这一组设置就是干这个的：

| 字段 | 说明 |
|---|---|
| 连接后运行终端启动队列 | 总开关 |
| 启动目录 | 比如 `/var/www/app` |
| 自动命令 | 每行一条，先执行 |
| 二跳命令 | 每行一条，用于堡垒机或二跳 shell，在自动命令之后执行 |
| 命令间隔（毫秒） | 默认 450 |
| 空闲超时（秒） | 默认 5 |
| 常用服务 | 每行一个服务名，会出现在终端的服务命令菜单里 |

"常用服务"配好之后，终端面板里就能一键看状态、看日志、跟日志、重启，不用每次敲完整的 `systemctl` 命令。

关于权限，界面上写得很清楚：**你手动输入的内容直接进终端；AI 发送的命令仍然需要审批**。远端不会因为"反正是服务器"就放宽。

## 15.4 Daemon 方式

远端跑一个 `willdeep-agent` 守护进程，WillDeep 通过 HTTP/WebSocket 连它。

配置项：Daemon URL（默认形如 `http://127.0.0.1:8765`）、Daemon token（存在钥匙串里）、远程工作区路径。

**部署建议直接照界面说的做**：把 daemon 绑在 `127.0.0.1` 上，然后通过 SSH 隧道访问。不要把它直接暴露在公网上——它能在那台机器上执行命令。

启动大致是这样：

```bash
willdeep-agent serve --workspace /path/to/project --token-file ~/.willdeep-agent-token
```

本地再开一条隧道：

```bash
ssh -N -L 8765:127.0.0.1:8765 user@your-server
```

然后在 WillDeep 里填 `http://127.0.0.1:8765` 和 token。

一个限制要知道：远端 daemon 上跑 Claude/Codex 这类外部执行器时，**目前还没有反向审批通道**，权限由 daemon 自己的工作区边界管。

## 15.5 用起来

配好之后，在输入框上方的工作区选择器里，"远程运行环境"分区会列出你配的 runtime，选一个就切过去了。

切过去之后：

- 文件面板显示的是远端的文件；
- 终端新建标签时可以直接连那台主机；
- Agent 跑的命令在远端执行；
- 审阅面板看的是远端仓库的改动。

**多台服务器同时连的时候**，强烈建议用终端状态条上的"提取主机标识"，它会把标签名改成实际主机名。开六个标签分别连不同机器、然后在错误的那个上执行了 `systemctl restart`，是一种很容易犯而且很难挽回的错误。

界面本身也有提醒：本地标签里你可能手工 `ssh` 到了别处，执行远程操作前先看提示符或者跑一下 `hostname`。

## 15.6 手机上用

「设置 → 账户与设备 → 手机网关」。它让你在手机上（Android App）接着看和推进 Mac 上的会话。

默认是**中继模式**：通过公共中继连接，手机在任何网络下都能用，不需要和 Mac 在同一个局域网，也不需要跑本地网关。

配对：扫二维码。要注销某台手机，办法是"轮换中继房间"——中继模式共用一个房间令牌，没有按设备的令牌，所以轮换之后所有已配对设备都要重新扫码。

两件事必须说清楚：

- **会话内容经中继服务器转发，传输层加密，但尚未端到端加密。** 涉密项目请自行判断。
- **Agent 执行、工具、补丁和文件访问仍然全部经过 Mac 应用**。手机是个远程操作界面，不是第二个执行环境。

高级设置里可以改监听地址端口、电脑名称、是否允许新设备配对、自定义中继服务。默认公共中继已经配好，一般不用动。

## 15.7 远端作业的几条经验

1. **先在终端手动跑一遍**再交给 Agent。远端环境差异比你想的大，PATH、locale、代理都可能不一样。
2. **生产机器用严格模式**，别用智能审核，更别用完全访问。
3. **别让它在生产上"顺手清理一下"**。任务描述里明确写"只读"，需要改动时单独开一次。
4. **保留现场再动手**。出问题先把 `top`、`df`、日志抓下来，再考虑修。
5. 远端跑长任务时，注意停止后远端进程未必真的停了——界面会提示"尚未确认远端进程退出"，别急着重跑一遍。
