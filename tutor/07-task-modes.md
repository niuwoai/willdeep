# 第 7 章 任务模式与计划

输入框下方那个带气泡图标的按钮就是任务模式。菜单里只有两项：**普通**和**目标**。它的说明文字写得很准：普通模式会按需规划并执行，目标模式会持续检查固定目标。

有一点要先澄清：早期版本有过独立的"计划模式"，现在没有了。规划没有消失，它变成了普通模式内部的一张卡片。所以本章讲的是两种模式，加一张贯穿始终的计划卡。

## 7.1 普通模式：默认，也是绝大多数时候该用的

普通模式下，Agent 自己判断这个任务要不要先规划：

- 一句话能做完的（"把这个函数的注释补上"），直接做。
- 需要多步的（"给这个模块加缓存，并补上测试"），先出一份计划，再按计划推进。

你不需要为了"让它先想清楚"而切模式，在任务描述里写清楚"先给我方案，我确认后再动手"同样有效，而且更灵活。

## 7.2 计划卡：读它、也改它

需要多步的任务会在对话里出现一张标题为"计划"的卡片。

**看什么**

- 卡片状态：已规划 / 已就绪 / 执行中 / 已完成 / 已中断 / 已拒绝。
- 步骤列表：点"展开计划"看全部，"收起计划"折回去。
- 输入框上方还有一个小胶囊，显示"第 N / M 步"，点开是"本轮进度"面板，按完成 / 进行中 / 待处理 / 失败分类统计。

**能改什么**

右键（或按住 Control 点）某个步骤，菜单里有：

- **编辑步骤** —— 改这一步的描述
- **在上方插入步骤… / 在下方插入步骤…** —— 补一步它漏掉的
- **删除步骤** —— 去掉一步不必要的
- **从此步骤重启…** —— 前面几步不用重做，从这里继续

卡片上还有**重新规划**，作用是让 Agent 自己改计划，你可以附一段修订说明。如果当前这一轮还在跑，你的备注会排队，等这一轮结束后生效。

**建议**：不要把计划当成合同去逐条较真。它的价值在于让你在第 2 步就发现方向不对，而不是等到第 9 步。发现不对就直接改步骤或者重新规划，代价很低。

## 7.3 目标模式：给长任务一条不会跑偏的线

目标模式适合这种任务：要跑很久、中途会有很多轮、你担心它做着做着就忘了最初要什么。

**怎么开**

1. 先给会话选好工作区。**没有工作区时"目标"这一项是灰的**，选不了。
2. 把模式切到"目标"。
3. 在"定义目标"里填两样东西：
   - **目标陈述**：我们要达到什么目标。一句话，写结果不写过程。
   - **验收清单**：每行一条，都是能判断真假的条件。

一份能用的验收清单长这样：

```
登录失败时返回明确错误码，不再返回 500
新增的回归测试覆盖空密码与超长密码两种情况
yarn test 全部通过
CHANGELOG 里有本次修改的条目
```

反例是"代码质量好""体验流畅"这类没法判真假的条目——写了等于没写，Agent 会自己给自己打勾。

**第一次可能会愣一下**：目标模式启动后会先走一段"Goal Teams 规划"，状态依次是独立评审 → 综合提案 → 证据仲裁 → 等待批准 → 执行中。规划期间工具是锁住的，界面看着像卡住了，其实在排方案。等它走到"等待批准"，你点头它才开工。

**跑起来之后**

- 输入框上方出现目标状态条，显示"进行中的目标"、已完成多少条清单项、已经跑了多久。
- 随时可以**暂停目标执行**，处理点别的，再**继续目标执行**。
- 想改目标或清单，打开编辑再改，改完继续。

**目标模式不会变出奇迹**。它解决的是"跑偏"和"提前宣布完成"，不解决模型能力不够。如果一个任务在普通模式下连方向都摸不到，切成目标模式只会让它以更整齐的姿态反复失败。

## 7.4 什么时候用哪一种

| 任务 | 用 | 理由 |
|---|---|---|
| 问一个问题、改一处小地方 | 普通 | 开销最低 |
| 改一个功能，涉及三五个文件 | 普通 | 让它自己出计划就够了 |
| 一整天的重构、迁移、批量整改 | 目标 | 有验收清单才不会越做越歪 |
| 你自己也说不清要什么 | 普通 + 先问后做 | 先让它调查、给方案，你确认完再进入执行 |
| 定时跑的例行任务 | 见[第 14 章](14-automation.md) | 模式不是重点，任务描述才是 |

## 7.5 和"先写设计再写代码"的关系

有些较大的改动，Agent 会先产出一张标题是"先写了设计"的卡片，上面有三个按钮：**按这份做**、**跳过，直接做**、**打开文档**。

这个行为可以关，在「设置 → Agent 外观」最下面，两个独立开关：

- **认出那些该先写设计的需求** —— 只在后台记录它本来会拦下什么，不打扰你。
- **先停下来写设计，再动代码** —— 真的拦，Agent 会在 `docs/` 下写一份文档然后等你。

关掉第二个就只剩静默记录；两个都关就完全不参与。

这张卡片的状态会保存下来，你现在不决定，明天打开 App 它还在。碰上跨模块、改数据格式、要改对外协议的任务，花两分钟读一遍设计再点"按这份做"，通常比直接放它去写代码省事。

## 本章检查点

- [ ] 你知道任务模式只有"普通"和"目标"两项
- [ ] 你能在计划卡上编辑一个步骤，或者从某一步重启
- [ ] 你写过一份每条都能判真假的验收清单
- [ ] 你知道目标模式需要先绑工作区
