# 第 10 章 审阅改动与提交

Agent 说"改好了"，这句话的价值等于零。真正能作数的是这一章讲的东西：改了哪些文件、每处改了什么、验证跑没跑通。

## 10.1 打开审阅面板

三条路：

- 会话标题行的图标条里点"审阅"；
- 输入框上方出现的变更汇总条，点一下直接进去；
- 在对话里点一个**已改动**的文件名，会直接跳进审阅并定位到那个文件。

打开时面板会自动变宽，因为 Diff 窄了没法看。

## 10.2 审阅范围

工具栏左上角的下拉决定你在看哪一批改动：

| 范围 | 看到的是 |
|---|---|
| **未提交** | 工作区里所有还没提交的改动（默认） |
| **未暂存** | 还没 `git add` 的部分 |
| **已暂存** | 已经 `git add` 的部分 |
| **上一轮提交** | 最近一次提交改了什么 |

日常验收用"未提交"就够。想确认"我刚才提交的到底带了什么进去"，切"上一轮提交"。

## 10.3 工具栏

- 绿色 `+N` / 红色 `-N`：这批改动新增和删除了多少行。数字大得离谱时先别急着看细节，先问它为什么改了这么多。
- **跳转到文件**：在改动的文件之间快速跳。
- **显示已更改文件 / 显示逐文件审阅**：两种视图切换，一个是文件清单，一个是逐文件看内容。
- **展开全部 / 折叠全部**。
- **刷新**：它刚改完你没看到新内容，点这个。

几种空状态是正常的，不是坏了："没有未提交的改动。"、"没有已暂存的更改。"、"不是 Git 仓库。"

**改动太大时面板会拒绝渲染**，并告诉你具体超了多少字节和多少行，建议你用 `git diff --no-ext-diff HEAD -- <path>` 在终端看。这是有意的：把十万行 Diff 塞进侧栏只会让整个窗口卡住。

## 10.4 补丁卡片：应用还是拒绝

有些改动不会直接落盘，而是先在对话里变成一张补丁卡片，标题写着"N 个变更等待审查"。

卡片上的操作：

- **查看 Diff / 收起 Diff**：先看再决定。
- **应用 / 拒绝**：单条处理。
- **全部应用 / 全部拒绝**：一次处理完。

卡片会显示计数：待处理几个、已应用几个、已拒绝几个、失败几个。如果某个改动其实已经在文件里了，它会告诉你"改动已存在，无需重复应用"。

要注意：**审阅面板里没有撤销按钮**。撤销的语义在补丁卡片上——拒绝就是不应用。已经落盘的改动要回退，走 Git（`git checkout --` 或 `git restore`），或者直接让 Agent 改回来。

## 10.5 提交与推送

面板底部是提交条：

1. 填提交信息。
2. 需要的话勾上"包含未暂存的更改"。
3. 点"提交"，或者按 **⌘↩** 提交并推送。

结果会明确告诉你是哪一种："提交成功。"、"已提交并推送。"、"提交成功，但推送失败：……"。第三种最容易被忽略，看到它就去处理推送问题，别以为已经推上去了。

处在游离 HEAD 时，界面会显示"游离分支"，这时候提交要格外小心。

## 10.6 一份验收清单

Agent 报告完成之后，按这个顺序过一遍，大部分问题在这里就能拦住：

1. **改动文件清单对不对**。有没有动到你没让它动的文件？有没有顺手"优化"了无关代码？
2. **每处改动看得懂吗**。看不懂就问它为什么这么改，别默认它是对的。
3. **测试是真跑了还是它说跑了**。看终端输出，看退出码。
4. **测试有没有被改**。"测试全绿"和"把测试改绿"是两回事，Diff 里一眼能看出来。
5. **版本号和 CHANGELOG 跟上了吗**（如果你的项目有这个要求）。
6. **有没有留下调试代码、注释掉的旧实现、临时文件**。

第 4 条尤其值得单独盯。测试文件出现在 Diff 里不一定有问题——补测试是好事——但断言被放宽、用例被删掉、跳过标记被加上，这些都要问清楚。

## 10.7 多人协作时的注意事项

如果这个仓库同时有别人（或者你自己的另一个会话）在改：

- 提交前先看清楚 Diff 里是不是混进了别人的改动。
- 用精确的 `git add <文件>`，不要 `git add -A`。
- 冲突严重的场景，考虑让不同会话跑在各自的 Git worktree 里（[第 5 章](05-workspaces-and-sessions.md)）。

## 本章检查点

- [ ] 你能在四种审阅范围之间切换，并说出各自看到什么
- [ ] 你用补丁卡片拒绝过一次不想要的改动
- [ ] 你知道审阅面板没有撤销，回退要走 Git
- [ ] 你知道"提交成功，但推送失败"是一种需要处理的结果
- [ ] 你会检查测试是不是被改松了
