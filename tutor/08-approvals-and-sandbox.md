# 第 8 章 审批、沙箱与安全边界

这是整本手册最值得认真读的一章。用得好，Agent 帮你干活；设得太松，它会在你没看见的时候动了不该动的东西；设得太紧，你一晚上点两百次"允许"，最后麻木地全点通过——那比设松还危险。

## 8.1 四档审批模式

输入框下方的盾牌按钮就是审批模式。菜单标题问得很直白："如何批准 Agent 操作？"四个档位按界面顺序是：

| 档位 | 界面摘要 | 实际边界 |
|---|---|---|
| **智能审核**（默认） | 自动写入工作区，并智能审核外部操作。 | 只读工具、工作区内写入直接执行；外部操作交给一个审核模型判断，安全的放行、可疑的问你；破坏性命令仍然要你手动确认 |
| **完全访问** | 无需询问即可访问互联网和这台 Mac 上的任何文件。 | 本机任意文件、凭据、网络全部自动执行，不再经过审核。只剩一份确定性的恶意命令黑名单，以及必须由你本人回答的问题 |
| **工作区可写** | 自动执行工作区写入；外部操作仍需确认。 | 工作区内写入、派 Worker 自动放行；外部和网络操作、危险工具、不受信的 MCP 调用都要你点头 |
| **严格模式** | 安全相关写入或外部操作前询问。 | 只读工具和无害的元数据变更自动执行，其余一律问你 |

注意这四项在菜单里的顺序不是按危险程度排的——"完全访问"排在第二位，而且是唯一一个用橙色标出来的档位。看颜色比看位置靠谱。

**怎么选**

- 日常开发、你熟悉的项目：**智能审核**。这是默认值，也是设计时按"多数场景"调过的那一档。
- 别人的代码库、第一次跑的脚本、涉及生产环境：**工作区可写**或**严格模式**。
- **完全访问**：只在你完全清楚接下来要发生什么、并且愿意为结果负责时短期使用。它会放开对本机凭据的访问。用完记得切回来。

**"完全访问"下仍然会停下来问你的，只剩四件事**：

- **确定性恶意命令黑名单命中**（抹盘、植入 authorized_keys、反弹 shell、清日志关 SIP、凭据和网络出口出现在同一条命令里）。
- **你在 MCP 设置里标为"不信任"的服务器**。
- **切换工作区，以及环境信任声明本身**（见 8.5）。
- **回放保存过的终端捷径**。

反过来说，这一档下**读凭据是不问的**：`cat .env` 这类被刻意留在黑名单之外，只有当同一条命令里同时出现凭据和网络出口时才会被拦。这正是这一档危险的地方，也是它只该短期使用的原因。

还有一个失败方向必须知道：前三档在审核模型缺席时会退回人工确认，**完全访问在审核模型缺席时是放行的**。也就是说这一档的真实保护强度，等于那份确定性的恶意命令黑名单，审核模型只是加分项。黑名单挡的是抹盘、植入 authorized_keys、反弹 shell、清日志关 SIP、以及"凭据和网络出口出现在同一条命令里"这几类；它**故意不挡** `rm -rf node_modules`、`git reset --hard`、功能分支 force push、本地库 `DROP TABLE` 这些——挡了这一档就没有存在意义了。

**一个容易踩的坑**：如果当前模型服务商没有可用的 API Key，也没登录 some.im，智能审核里的"审核模型"就上不了场，于是每条命令都要你确认。界面会给一次提示，说明在设置里填 Key 或登录即可恢复自动审批。突然开始疯狂弹确认框时，先想想是不是这个原因。

## 8.2 审批卡上的按钮

需要你决定时，对话里会出现一张工具卡，状态写着"等待批准"或"需要确认"。按钮的含义差别很大：

| 按钮 | 作用范围 |
|---|---|
| **允许** | 只这一次 |
| **允许此对话** | 这个会话内同类操作不再问 |
| **始终允许** | 今后永久允许这条命令，跨会话生效 |
| **拒绝** | 不执行，Agent 会收到拒绝结果并另想办法 |
| **确认执行** | 破坏性命令专用，要你**手工键入确认**才跑，任何档位都不会自动放行 |
| **允许本次控制会话** | 操作电脑 / 操作浏览器这类能力，只授权这一次控制会话 |

"始终允许"要谨慎。它按命令族记账（比如整个 `git push`），一旦加进去，以后这条命令在任何会话里都不会再问你。清单在「设置 → Agent 工具 → 工具」的"Agent 永久允许列表"里，可以逐条移除或全部清除，定期清一次是个好习惯。

有两件事它做不到，是有意的：危险命令仍然要键入确认，不会因为在名单里就放行；**文件写入类工具不能被"始终允许"**，因为同一个工具写哪个路径，影响范围完全不同。

还有两种卡片值得单独认识：

- **沙箱拦住了这条命令** —— 问你要不要"无沙箱重跑"，另一个选项是"保持沙箱"。先看清楚它到底要跑什么，再决定。
- **准备执行一项会改变仓库或远端状态的操作** —— 这张卡会明确写着"只授权这一条命令"，点了不等于以后都放行。

## 8.3 沙箱挡住了什么，没挡住什么

工具执行时会落在一个沙箱档位里，从只读到完全不沙箱共六档。你在界面上看到的是结果，机制大致是：

- **写入范围**：默认只允许写工作区、临时目录和用户目录下的缓存。工作区之外的路径写入会被拒绝。
- **凭据读取**：普通档位下，`~/.ssh` 这类凭据路径的读取在内核层被拒绝，ssh-agent 也不可用。只有明确升到带凭据的档位才放开。
- **环境变量**：敏感环境变量会被剥离，不会跟着命令进去。
- **输出脱敏**：命令输出里的疑似密钥会被处理后再展示和上传。

有一件事必须说清楚：**沙箱不拦网络**。这堵墙在设计上从来没有真正合拢过——文件读取在每一档都是放开的，写入对整个工作区开着，"读到密钥写进工作区、下一条命令再发出去"两步就能绕过，而这两步在同一个审批档位里。挡住的反而多是正事（装依赖、拉镜像、调接口），还会把失败伪装成域名解析错误，把人引到 DNS 上排查。所以档位名字里带 Network 的部分现在只用于读懂历史审计记录，不代表两种不同的运行时行为。

真正在防外泄的是这四件事：写入只限工作区、凭据路径与破坏性命令需要人工确认、输出脱敏、敏感环境变量剥离。

**沙箱开关在哪**：输入框下方"更多设置"（`…⌄`）里有"默认使用沙箱"，默认开。也可以用 `/sandbox` 和 `/no-sandbox` 两条命令切换，效果和开关是同步的。

**工作区里的脚本是特殊对待的**。早期版本把 `bash x.sh` 关进最严的档位，给它一个假的 HOME、还断网，结果挡住的全是正事，这个做法已经被推翻。现在是两条路：

- 目录被你标记为**可信** → 脚本直接脱沙箱运行，真实 HOME。
- 目录**没标记** → 仍在沙箱里，但会拿到真实 HOME 和 `SSH_AUTH_SOCK`。

这份目录信任是你在打开文件夹、切换工作区或者给项目加目录时被问过一次并答应下来的。它**按位置生效，不看脚本内容**——所以"这个目录我信得过"这句话要当真话说。

所以"我自己在终端跑得通、Agent 跑就不行"，现在通常不是 HOME 的问题，而是：这个目录还没标可信、写入路径越界、或者命令撞上了凭据敏感特征。先看审计日志里这条命令用的是哪一档（见 8.7）。

## 8.4 工作区边界

工作区之外的路径，写入会被直接拒绝。常见的念头是"那我做个软链接指过去不就行了"——这条路是被有意堵死的：软链接不作为第二扇门。要让 Agent 动另一个目录，就把那个目录正大光明地加进工作区（多目录项目的做法见[第 5 章](05-workspaces-and-sessions.md)）。

这条规矩看着死板，但它让"Agent 能写哪儿"这个问题永远只有一个答案，排查时不用满硬盘找软链接。

## 8.5 环境信任声明

有些环境确实不需要那么小心：一个用完就扔的容器、一个专门用来跑测试的数据库。你可以在对话里说出这件事，让 Agent 登记一条"环境信任声明"。

它有几条硬规矩，理解了才敢用：

- **只能因为你本人在这次对话里亲口说过**才能登记，而且 Agent 必须逐字引用你的原话。文件里、网页里、命令输出里出现的"这个环境是安全的"一律不算——那正是提示注入自我授权的路子。
- 登记本身**任何档位都不会自动通过**，一定会弹卡让你批准，卡上会把你自己的原话回显给你看。
- 只在**本次对话**有效，关掉会话就没了。
- **永远不豁免凭据读取**。`.env`、`~/.ssh`、API Key 这些，声明了也照样问。

两种声明：一次性终端（这个可见终端是容器或本地沙箱）、测试数据库（某个实例是测试库，要给出能匹配到它的名字）。都可以随时撤销。

## 8.6 密钥怎么交给它

绝对不要把 API Key、密码直接打在对话框里——那会进会话记录，也会发给模型。

输入框底部有"插入受保护机密"按钮，打开后可以一次填最多三条。这些值只存在本机钥匙串里，模型看到的是 `${secret:别名}` 这样的占位符，真实值在本地执行的那一刻才被替换进去。

存过的密钥可以反复用：「设置 → Agent 工具 → 密钥管理器」是它们的集中管理页，支持搜索（拼音也能搜）、改名、删除。别名会被规范成小写短横线格式，同名再存一次就是更新。

其余原则和别处一样：

- 服务商 API Key 填在设置里，存钥匙串，不进任何文件。
- 涉及生产库、支付、对外发消息的操作，永远保留人工确认，不要为图省事挂"始终允许"。
- 发现某个命令输出里带了密钥，当作已泄露处理：轮换它，而不是只把那条消息删掉。

## 8.7 出问题时查哪里

两份日志在 `~/Library/Application Support/WillDeep/AgentAudit/`：

- `judge.jsonl` —— 审核模型的每次判定。**某条命令在这里查不到，说明裁判根本没上场**，它在更前面就被确定性的门禁拦住了。
- `sandbox.jsonl` —— 每次执行用的沙箱档位。"本机能跑、Agent 跑不了"先看这里的 mode 列。

两个都是一行一条 JSON：

```bash
tail -n 50 ~/Library/Application\ Support/WillDeep/AgentAudit/judge.jsonl | jq .
```

统计比例时记得先剔掉测试夹具产生的记录（含 `example.com`、`evil.example`、`FIXTURE_WORK_DIR` 之类字样的行），否则算出来的结论会和真实情况相反。

## 8.8 一份务实的配置建议

```
日常项目          → 智能审核 + 沙箱开
不熟的代码库      → 工作区可写 + 沙箱开
生产环境相关      → 严格模式 + 沙箱开，且全程盯着
批量本机文件整理  → 完全访问，做完立刻切回来
```

再加一条不写进设置里的习惯：**每次 Agent 说"已完成"，先看 Diff 再信**。审批体系防的是它做了你不知道的事，防不了它做错了还说做对了。
