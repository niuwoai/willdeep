# 第 5 章 工作区与会话

工作区决定 Agent 能碰什么，会话决定这段工作记在哪儿。这两件事设好了，后面所有能力才有落脚点。

## 5.1 给会话绑一个工作区

输入框上方第一个控件就是工作区选择器。没选时它显示"选择文件夹"。

点开菜单，最下面是"选择文件夹…"。选一个目录之后：

- 这个会话的读写范围就锁定在这个目录里；
- 文件面板、审阅面板、终端的默认目录都跟着它；
- 侧边栏会把这个会话归到对应的工作区分组下。

有一点要注意：**从菜单里"选择文件夹…"会同时新建一个会话**并绑到那个目录，而不是把当前会话搬过去。想给当前会话换目录，用菜单中间的"切换工作区"分区，那里列着你最近用过的目录和历史会话的根目录。

**没有工作区也能用**的是：聊天、终端、浏览器、预览。需要工作区的是：文件面板、审阅面板、目标模式，以及一切要改文件的活。

## 5.2 工作区菜单里还有什么

| 分区 | 项 | 用途 |
|---|---|---|
| 当前文件夹 | 在 Finder 中显示 / 复制路径 / 复制分支名 | 常用的小工具 |
| Git worktree | 新建 worktree… / worktree 列表 / 移除当前 worktree… / 清理失效 worktree | 见 5.3 |
| 切换工作区 | 最近用过的目录 | 换项目 |
| 远程运行环境 | 已配置的 SSH runtime | 见[第 15 章](15-remote-runtimes.md) |

旁边的"运行位置"只有两项：**本地处理**和**新工作树**。不是 Git 仓库时，"新工作树"是灰的。

## 5.3 用 Git worktree 隔离同时进行的任务

如果你经常同时开好几个会话改同一个仓库，它们会互相踩脚：一个在改文件，另一个 `git status` 看到的就是花的。

"新工作树"解决这个问题：它给这个会话单独开一个 Git worktree，改动落在独立目录里，和主工作区互不影响。会话行上会出现一个 worktree 徽标提醒你。

用完之后记得清理：工作区菜单里有"移除当前 worktree…"和"清理失效 worktree"。

**代价**要说清楚：每个 worktree 是一份独立的检出，编译缓存不共用。对编译时间长的大项目，来回开 worktree 可能比撞车本身更耗时间。小改动、脚本类项目适合开；重型项目建议就在主工作区里排队干活。

## 5.4 多目录：把几个文件夹拼成一个项目

一个任务要同时看后端和前端两个仓库时，把它们做成"项目"。

在侧边栏工作区分组的标题上右键 → **升级为项目…**，然后：

1. 填项目名称。
2. 在"源文件夹"里点"添加文件夹"，把其它目录加进来。
3. 保存。

之后这些目录都在同一个项目下，会话的读写范围覆盖全部源文件夹。

几条规则值得先知道：

- 项目至少保留一个文件夹，移掉最后一个等于删掉这个项目。
- 删除项目时，弹窗会明确告诉你有多少会话会被一起永久删除，以及哪些会话因为同时属于别的项目而被保留。看清楚再点。
- **不要用软链接代替加目录**。写入判定不认软链接这条旁路，要多一个目录就正式加进来（[第 8 章](08-approvals-and-sandbox.md)）。

## 5.5 会话管理

先说一条影响使用习惯的机制：**每个会话独占一个运行时**。切到别的会话不会打断正在进行的请求，其它会话继续在后台跑，回来还能看到完整记录。所以"等它跑完"这件事从来不需要你干等着。

**新建**：⌘N、侧边栏的"新聊天"、或者斜杠命令 `/new`。默认标题是"新对话"，发过消息之后可以右键"用 AI 总结标题"，让它自己起个像样的名字。

**分组**：按工作区自动分。组可以整体折叠，组内默认显示 5 条。

**置顶**：常用的会话置顶，会排到最上面独立的"置顶"分区。

**归档**：不想看又不舍得删的，归档。它会进入所属工作区组里的"已归档"子分区。
注意：如果这个会话带着活跃的定时任务，归档会弹确认，告诉你有几个任务会被一并停掉并移除。这是真的会停，不是暂停。

**删除**：右键"删除会话"，确认框会写明"及其全部消息将被永久删除，无法撤销"。删了就没了，没有回收站。

**搜索**：**⇧⌘P** 按标题搜会话和项目；**⌘F** 在当前会话的对话正文里搜。

**继续**：右键菜单里的"在新聊天中继续"和"在新工作树中继续"，会带着上下文开一个新会话。上下文快满时用这个比在原会话里硬撑更划算（[第 16 章](16-context-and-cost.md)）。

**其它右键项**：在 Finder 中显示、复制工作目录、复制会话 ID、复制深度链接、在新窗口中打开转录、标记为已读/未读。

## 5.6 一套够用的组织习惯

用了几周之后，会话数量会上到几百个。几条习惯能让侧边栏一直可用：

1. **一个任务一个会话**。想起来别的事就新开一个，别在同一个会话里换题目——上下文会越来越贵，检索也会变难。
2. **做完就归档**。归档不影响搜索，但侧边栏会清爽很多。
3. **正在跟进的置顶**，数量控制在五条以内。
4. **多仓库的活先建项目**，别靠"记得我在哪个目录"。
5. 跑定时任务的会话单独留着，不要归档（归档会停掉任务）。

## 本章检查点

- [ ] 你给会话绑过工作区，也用"切换工作区"换过一次
- [ ] 你知道"选择文件夹…"会新建会话，而不是搬当前会话
- [ ] 你至少建过一个多目录项目
- [ ] 你知道归档带定时任务的会话会停掉那些任务
- [ ] 你会用 ⇧⌘P 和 ⌘F 两种搜索
