# 第 17 章 排错与取证

这一章按症状组织。遇到问题先在 17.1 的表里找，找到了跳到对应小节。

## 17.1 症状速查

| 症状 | 先看 | 小节 |
|---|---|---|
| 每条命令都要我点确认 | 审核模型是不是没配上 | 17.2 |
| 本机终端能跑，Agent 跑就失败 | `sandbox.jsonl` 里这条命令的档位 | 17.3 |
| 它说完成了，但文件没变 | 补丁卡片是不是还没应用 | 17.4 |
| 插件页面白屏或者一直骨架屏 | 是不是装了两份 | 17.5 |
| 点会话打不开，提示历史文件缺失 | 会话文件是不是被外部删了 | 17.6 |
| 请求报错、上下文满 | 压缩和窗口 | 17.7 |
| 定时任务没跑 | 会话是不是被归档了 | 17.8 |
| 手机连不上 | 中继模式和配对 | 17.9 |
| 更新装不上 | 签名验证与 CDN 缓存 | 17.10 |
| 说不清楚，就是不对 | 导出诊断包 | 17.11 |

## 17.2 一直要我点确认

最常见的原因不是你设错了审批档位，而是**审核模型上不了场**。

智能审核这一档，白名单外的命令要交给一个审核模型判断。如果当前服务商没填 API Key，也没登录 some.im，这个模型就调不动，于是每条命令都退回人工。界面会给一次提示，写着"当前没有可用的安全裁判……在设置里为当前模型服务商填入 API Key，或登录 some.im，即可恢复自动审批"。

**怎么确认**：看 `judge.jsonl`。

```bash
tail -n 30 ~/Library/Application\ Support/WillDeep/AgentAudit/judge.jsonl | jq .
```

- **这条命令在文件里根本查不到** → 裁判没上场，它在更前面就被确定性的门禁拦下了。这类拦截通常是命令里出现了敏感特征（凭据路径、危险动作的字样）。
- **查得到，verdict 是 deny** → 裁判判的，`detail` 字段写了理由。
- **查得到，但结果是 unavailable** → 调用失败了，看是网络还是 Key。

还有一种情况：某条命令的写法碰巧撞上了敏感字样。比如命令里带 `.env` 这样的子串，即使真实含义完全无关，也可能被前置门禁拦下。换个等价写法通常就过了。

## 17.3 本机能跑，Agent 跑不了

先看这条命令实际用的沙箱档位：

```bash
tail -n 50 ~/Library/Application\ Support/WillDeep/AgentAudit/sandbox.jsonl | jq -r '[.timestamp,.toolName,.mode,.approvedBy,.summary] | @tsv'
```

几个高频原因：

- **这个目录还没被标记为可信**，所以工作区脚本仍然关在沙箱里跑。这是现在最常见的一条。
- **写入路径在工作区之外**，直接被拒。
- **需要读凭据**（`~/.ssh`、`.env` 之类），这类读取在普通档位是内核级拒绝的。

对应的解法，按优先级：

1. 让这个目录进入工作区信任——打开文件夹、切换工作区或给项目加目录时它会问你，答过一次就记住，之后这个目录里的脚本直接脱沙箱跑。
2. 用"无沙箱重跑"那张卡（它会明确告诉你要跑什么）。
3. 临时用 `/no-sandbox` 关掉本会话的沙箱，做完用 `/sandbox` 开回来。

不要直接把审批档位调到"完全访问"来绕过沙箱问题——那是两件事，调了也未必解决，还顺手把别的防线放开了。

## 17.4 它说改好了，但文件没变

三种可能，按概率排：

1. **改动还停在补丁卡片上等你点"应用"**。卡片上会写着"N 个变更等待审查"。
2. **它改的是另一个路径**。看工具卡里的实际路径，尤其是多目录项目和 worktree 会话。
3. **它真的没改，只是说改了**。打开"审阅"面板看 Diff，空的就是没改。这种时候直接把 Diff 是空的这件事告诉它。

第 3 条比你以为的常见，这也是[第 10 章](10-review-and-commit.md)反复强调看 Diff 的原因。

## 17.5 插件白屏

先确认是不是**装了两份同名插件**——内置的一份加本地安装的一份，两份混装会让页面白屏或者骨架屏不消失。

处理顺序：

1. 插件中心里看这个插件有没有重复条目，停用或卸载多余的那份。
2. 连续崩溃三次的话，自动重载会停下来并提示你停用或回滚，照做。
3. 还不行就回滚到上一个版本。
4. 要看具体报错，打开"允许对插件页面使用网页检查器"，重开页面，用 Safari 的"开发"菜单连上去看。看完记得关掉。

## 17.6 会话打不开

弹窗写着"本地历史文件缺失"，意思是磁盘上那个会话 JSON 不见了或者读不出来。

这时候 WillDeep 有意**保留侧边栏条目、不用空会话覆盖原文件**，就是为了让你有机会从备份恢复。

- 有 Time Machine 或者别的备份，从 `~/Library/Application Support/WillDeep/agent-sessions/` 里恢复那个文件。
- 没有备份，那这个会话的内容找不回来了，删掉条目即可。

顺带一句：不要手工删 `agent-sessions/` 里的文件来"清理"，界面侧的索引会和磁盘对不上。归档和删除走界面。

## 17.7 请求报错、上下文满

- **上下文满导致的失败**：先压缩，再考虑"在新聊天中继续"。
- **反复报 400 之类的请求错误**：多半是单次请求太大。检查是不是一次性附了很大的文件，或者挂了太多技能。
- **回复被截断**：Anthropic 那边有"回复上限"设置（默认 32768），调大一点。
- **模型不支持读图**：配一个"图像理解"模型（[第 3 章](03-models-and-providers.md)）。
- **总是在排队**：并发上限默认 3，可以调到 5–6。

## 17.8 定时任务没跑

按顺序查：

1. 任务本身是不是被停用了（"已暂停"）。
2. **它所在的会话是不是被归档了**——归档会停掉并移除活跃的定时任务，这是最常见的原因。
3. 看运行历史。有记录但结果是"已中断"，说明跑的时候 App 退出了。
4. 完全没有记录，看 `~/Library/Application Support/WillDeep/agent-routines/` 里有没有这个任务的定义。
5. Prompt 不是自包含的，跑起来了但什么也没做出来——这属于写得不对，不是没跑。

## 17.9 手机连不上

- 传输模式默认是"中继"，不需要同一个局域网。确认没被改成局域网模式。
- 确认"允许新设备配对"是开着的，然后重新扫码。
- 想踢掉某台设备，只能"轮换中继房间"，之后所有设备都要重新配对。
- Mac 这边 App 得开着——手机只是操作界面，执行全在 Mac 上。

## 17.10 更新装不上

- 更新包必须通过签名验证才会安装，验证不过会直接失败，这是设计如此，不是坏了。重试一次，还不行就从官网重新下载完整包。
- 刚发版的头几分钟，官网下载链接可能还是 CDN 上的旧文件。走 App 内的更新流程不受这个影响。
- 预发布版本有时只编译 Apple Silicon。Intel 机器装到这种包会出问题，用正式版本。

## 17.11 导出诊断包

说不清楚的问题，直接导一份给能看的人：「设置 → 更新 → 诊断导出」。

**先选范围**：整个项目，还是单个会话。

**再选包含多少**，这一步决定了里面有什么：

| 档位 | 里面有什么 |
|---|---|
| **只发时间线** | 每个回合的耗时和计数。**不含对话正文，也不含命令**。诊断"为什么慢"就够用 |
| **完整** | 额外包含选中会话的完整正文，以及这段时间的沙箱与审批日志——那两份日志里是实际执行过的命令 |

界面会直接告诉你包里装了多少会话、多少条时间线、多少条命令记录、时间范围，以及一句明确的"包含你的对话正文和执行过的命令"或者"不含"。

**选"完整"之前想一想**：里面有你跑过的所有命令。只发给你愿意让他看到这些的人。

## 17.12 看系统日志

```bash
/usr/bin/log show --predicate 'process == "WillDeep"' --last 30m --info
```

必须写 `/usr/bin/log` 的全路径。在 zsh 里直接敲 `log show` 会命中 shell 内建命令，报的错还容易被 `2>/dev/null` 吞掉，看起来像"没有日志"。

## 17.13 报问题时带上什么

在 <https://github.com/niuwoai/willdeep/issues> 提问题时，带上这几样能省好几轮来回：

1. **版本号**（关于 WillDeep 里的那串，比如 `1.375.0-rc3`）
2. **macOS 版本和芯片**（Intel 还是 Apple Silicon）
3. **复现步骤**：做了什么 → 期望什么 → 实际什么
4. **相关截图**（发之前用 `/image-redact` 打个码）
5. **诊断包**（能公开的话）

不要贴带着 API Key、服务器地址、私有代码的日志。真要贴，先脱敏。

## 本章检查点

- [ ] 你知道"一直要我确认"先查 `judge.jsonl`
- [ ] 你知道"本机能跑 Agent 不能"先查 `sandbox.jsonl` 的档位
- [ ] 你导出过一次诊断包，并且知道两个档位的区别
- [ ] 你知道查系统日志要写 `/usr/bin/log` 全路径
