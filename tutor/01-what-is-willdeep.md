# 第 1 章 认识 WillDeep

这一章不需要你动手。读完之后，你应该能回答三个问题：WillDeep 到底替你做什么、它是怎么组织一次工作的、哪些事它做不到。

## 1.1 一句话定位

WillDeep 是一个 macOS 原生的 **Agent 工作台**。你交给它一个目标，它在你指定的目录里读文件、跑命令、改代码、连服务器、生成图片，然后把改动和执行记录摆回同一个界面里让你核对。

关键词是"动手"。对话式 AI 给你一段建议，执行是你的事；WillDeep 给你的是已经执行完、可以逐条检查的结果。

## 1.2 和聊天机器人的四个区别

| | 对话式 AI | WillDeep |
|---|---|---|
| 工作对象 | 一段文本 | 一个目录（工作区）里的真实文件 |
| 动作 | 只输出建议 | 读写文件、执行终端命令、访问网页、调用外部服务 |
| 一次交互的长度 | 一问一答 | 一个目标可以跨几十轮，中途可以暂停、追问、改方向 |
| 你要做的事 | 复制粘贴 | 审批关键动作、检查 Diff 与测试输出 |

这四条决定了使用姿势的不同。用对话式 AI 时，描述得含糊一点也无所谓，反正结果由你落地。用 WillDeep 时，**目标描述的精确度直接决定它动了哪些文件**，所以第 6 章会专门讲怎么写任务描述。

## 1.3 一次任务的完整循环

不管任务大小，WillDeep 内部都在跑同一个循环：

```
你描述目标
   ↓
Agent 理解上下文（读项目文件、读规则、读历史）
   ↓
Agent 调用工具（改文件 / 跑命令 / 查网页 / 派子任务）
   ↓
遇到需要授权的动作 → 弹审批卡 → 你决定
   ↓
Agent 汇报结果，你在"审阅"面板看 Diff、在终端看输出
   ↓
不满意 → 继续提要求，回到第二步
```

这个循环里有三个位置是**你必须在场**的：一开始的目标描述、中途的审批、最后的验收。其余环节可以完全交出去。手册后面的章节基本是围绕这三个位置展开的。

## 1.4 七个核心概念

后面每一章都会用到这些词，先在这里说清楚。

**会话（Chat）**
一次任务的完整记录：你说了什么、Agent 做了什么、调用了哪些工具、产出了什么。会话在左侧边栏里排列，可以分组、置顶、归档、搜索。关掉 App 也不会丢。

**工作区（Workspace）**
这次会话允许读写的目录范围。没有选工作区时，Agent 只能聊天，不能碰你的文件。工作区可以是一个项目根目录，也可以同时挂多个目录。工作区之外的路径，写入会被直接拒绝——这是第 8 章要展开的"工作区边界"。

**运行位置（Runtime）**
命令究竟在哪台机器上执行。默认是"本地处理"，也就是你这台 Mac；也可以切到 SSH 主机或远端的 `willdeep-agent` 守护进程，让 Agent 直接在服务器上干活，结果仍然显示在你眼前的窗口里。见第 15 章。

**模型（Model）**
驱动 Agent 思考的大模型。可以用 some.im 的"省心托管"（不用自己配 Key），也可以填自己的 API Key、接自定义服务商，或者跑本机的本地模型。同一个会话中途可以换模型。见第 3 章。

**审批模式（Approval）**
Agent 动手前要不要先问你。WillDeep 提供几档不同松紧的策略，从"每一步都问"到"只有危险动作才问"。默认是"智能审核"。见第 8 章。

**Worker（子 Agent / 后台 Worker）**
把子任务派给另一个 Agent 去跑。调查、实现、验证可以并行，主会话继续和你对话。派出去的 Worker 在"后台任务"面板里能看到进度，也能单独停掉。见第 11 章。

**交付物（Artifact）**
这次任务留下的可验证结果：代码改动、测试输出、生成的图片和视频、写好的文档。验收看交付物，不看 Agent 自己说"我完成了"。

## 1.5 它适合什么工作

从实际使用看，收益最明显的是这四类：

- **改一个你熟悉的项目**：修 bug、加功能、补测试、做重构。你知道验收标准，Agent 负责跑腿。
- **摸一个你不熟的项目**：让它先读一遍、画出模块关系、定位某个行为在哪实现，比自己 grep 快。
- **远端维护**：连上服务器，查日志、看进程、改配置、重启服务，过程和结果都留在会话里可回溯。
- **重复流程**：每天/每周固定要跑的检查、汇总、生成，交给定时任务（第 14 章）。

## 1.6 它的边界

这一节比上一节重要。买椟还珠的用法大多来自对边界的误解。

**它不保证正确。** 模型会编造、会误判、会把测试改绿而不是把代码改对。所有"我已完成"的声明都要用交付物核对：看 Diff、看测试输出、自己跑一遍。

**本地工作区不等于数据不出本机。** 只要你用的是云端模型，任务需要的上下文（文件内容、命令输出）就会发给对应服务商。涉密项目请先确认模型来源，必要时改用本地模型。

**沙箱不是保险箱。** 沙箱限制写入范围、剥离敏感环境变量、对危险命令要求人工确认，这些能显著降低误操作概率，但不构成"零风险"。凡是删除数据、对外发布、动生产库和密钥的操作，都应该保留人工确认。

**长任务的恢复能力因任务而异。** 中断后能否无损续跑，取决于任务类型和执行器。已经发出去的外部动作（发过的消息、调过的接口）不会因为你点了停止就回滚。

**版本差异是常态。** 仓库版本、预发布版本和官网下载版本可能不同，界面也会随之变化。你看到的入口名字和本手册对不上时，先看「WillDeep → 关于 WillDeep」里的版本号。

## 1.7 系统要求与开源情况

- 系统：macOS 13.7 及以上，Apple Silicon 与 Intel 都支持（预发布版本有时只编 Apple Silicon）。
- 许可：核心代码按 Apache License 2.0 开源，可以自行阅读实现、从源码构建。商业产品与服务边界见仓库根目录的 `OPEN_CORE.md`。
- 反馈：问题和建议提到 <https://github.com/niuwoai/willdeep/issues>。
