# 第 13 章 扩展生态

WillDeep 自带的工具覆盖了文件、终端、浏览器、媒体这些通用场景。剩下的——你们公司的内部系统、你自己那套做事流程、别的 AI CLI——靠这一章的四种方式接进来。

| 方式 | 接进来的是什么 | 配在哪 |
|---|---|---|
| **技能（Skill）** | 一套做事的说明书 | 设置 → Agent 工具 → 技能 |
| **MCP** | 外部系统的工具 | 设置 → Agent 工具 → MCP |
| **插件** | 一个完整的页面或服务 | 侧边栏 → 插件中心 |
| **外部执行器** | 别的编程 CLI | 设置 → 代理档案 → 执行器 |

## 13.1 技能：把"该怎么做"写下来

技能是一份 Markdown（`SKILL.md`），写明"什么时候用它、按什么步骤做"。挂上之后，Agent 做这类任务时就按你写的流程走，而不是每次现编。

**怎么用**：输入框里打 `$`，搜索并选中一个技能，输入框上方会出现一个 chip。搜索支持中文关键词，即使技能本身是英文写的。

**四类来源**：

- **内置技能** —— 随 App 发行，四十来个，覆盖浏览器操作、图片生成、日报、计划模式、定时任务、系统信息、网页抓取等。
- **用户技能** —— 你自己写的，放在 `~/.willdeep/skills/<名字>/SKILL.md`。
- **插件技能** —— 插件带来的。
- **技能市场** —— 内置的静态目录，可以一键安装第一方技能（PPT 结构、PDF 设计、图片处理、发布守卫、静态站点发布、MCP 构建等）。市场技能需要的凭据以引用形式写进技能文件，真值存钥匙串。

**自己写一个**：设置里点"新建技能"，填名称和描述，正文写清楚 Agent 该在什么时候、以什么方式使用它。

**自动提取**：默认开着。WillDeep 会从你的对话里发现可复用的流程，浮现成技能候选。有个门槛——工具调用少于 6 次的对话直接跳过，避免把随口一问变成技能。如果它拒绝创建，会说明原因，比如"实际工具执行证据不足"。

## 13.2 MCP：把外部系统变成工具

MCP 是一个开放协议。一个 MCP 服务器暴露一组工具，接上之后这些工具就出现在 Agent 的工具表里。

「设置 → Agent 工具 → MCP」，点"新建 MCP 服务器"：

| 字段 | 说明 |
|---|---|
| 服务器名称 | 自己起 |
| 传输方式 | `stdio`（本机进程）或 `streamable-http`（远端） |
| 命令路径 / 参数 | stdio 用，填绝对路径和空格分隔的参数 |
| URL / 请求头 | http 用，请求头每行一条，如 `Authorization=Bearer ...` |
| 环境变量 | 每行一条，如 `HTTPS_PROXY=http://127.0.0.1:7890` |
| 超时 | 默认 30 秒，可设 1–180 |

**信任级别**是这一页最重要的设置，三档：

- **不信任** —— 每次调用都问你。选了这一档，针对它的"始终允许"规则全部失效。
- **默认** —— 只读类调用自动执行，写入操作会问。
- **完全信任** —— 所有调用自动执行，**包括写入**。

接一个你不完全了解的 MCP 服务器时，先用"不信任"跑几天，看清楚它都调什么，再决定要不要放宽。

页面上还列着几种来源：用户自己配的、从 Cursor 的 `mcp.json` 读来的、从 Codex 配置读来的、插件提供的。插件那一组不能在这里编辑或删除——它们的定义在插件包里，插件停用就消失。

推荐区里有 Playwright MCP（含国内镜像版本），用的是 `npx -y`，首次启动不会卡在交互式确认上。

## 13.3 插件：一个完整的页面

插件比技能和 MCP 都重，它能往侧边栏加一个自己的页面、带自己的服务、贡献自己的技能和 MCP 服务器。

侧边栏 → 插件（插件中心），安装来源有两种：

- **从目录或 ZIP 安装…**
- **从 Git 安装…** —— 填仓库地址，可选分支或标签

安装是**两阶段**的：先 stage 并校验，生成一份"这个插件要什么权限"的清单给你看，你点"批准并启用"之后才真正生效。激活过程不会执行插件包里的构建脚本。

**权限清单**值得逐条看：读取你的会话、替你给 Agent 发消息、读取工作区文件、修改工作区文件、在本机执行命令、访问网络、使用钥匙串里的凭据、调用聊天模型、生成图片、写入剪贴板、发送通知。升级时新增权限会重新问你。

其它操作：启用 / 停用、固定到侧栏、检查更新、回滚、卸载、在 Finder 中显示、诊断。

插件页面连续崩溃三次会自动停止重载，并提示你停用或回滚——这比无限重启循环友好得多。

开发者选项里有个"允许对插件页面使用网页检查器"，默认关着。它的说明写得很实在：开启不会给页面多一分能力，但检查器能读到页面内存里的一切。

## 13.4 外部执行器：把活交给别的 CLI

如果你已经在用 Claude Code、Codex CLI 这类工具，不必二选一。WillDeep 可以把某一轮或某个工种交给它们执行，自己负责调度、展示和审批。

**三层配置**：

1. 「设置 → 运行时 → 本机 Agent」—— 这里只做**发现**，扫常见安装路径和 PATH，不启动它们。界面会区分"可直接委派"和"仅发现"：

   | 可直接委派 | 仅发现 |
   |---|---|
   | Claude Code、Codex CLI、Hermes、OpenCode、Cursor CLI、Cline CLI | Aider、Gemini CLI、Qwen Code、Goose、Amp、Crush |

2. 「输入框上方的执行器选择器」—— 这一轮交给谁。选了非 WillDeep 的执行器之后，**模型选择器会整个消失**，因为那时模型由外部 CLI 决定。这是刻意的，不是 bug。

3. 「设置 → 代理档案 → 执行器」—— 把某个工种固定指派给某个外部 CLI，还能填对方的原生 profile 名。选了外部执行器之后，这个档案里的"专属提示词 / 技能包 / 工具集"会被禁用，因为对方自带一整套 harness，送不进去。

**审批怎么走**：Claude Code 和 Codex 走结构化接入时，它们的命令、文件写入、终端和权限请求都会回到 WillDeep 让你批。走兼容模式时则是对方 CLI 自己的策略，加上 WillDeep 的外层沙箱。

## 13.5 技能包（专家）

还有一层是"技能包"，它管的是 **Agent 能用哪些工具**：

| 技能包 | 打开什么 |
|---|---|
| **浏览器操作** | 截图、点击、填表、操作 Chrome 标签页 |
| **Web 编程** | 截图转 UI、本地预览、浏览器验收、dev server 编排 |
| **短剧制作** | 短剧规划、分镜、媒体任务和制作包工具 |

有一条设计值得知道：**内置浏览器面板故意不受"浏览器操作"技能包限制**。你想打开聊天里出现的一个局域网地址，那是普通浏览，不该藏在开关后面。受限的是 Agent 的自动化能力。

技能包一旦在本次会话里介入过，本会话内就不能再关掉。

## 13.6 什么时候用哪个

| 你想要 | 用 |
|---|---|
| 让它按我的流程做某类事 | 技能 |
| 让它能操作我们公司的系统 | MCP |
| 我要一个自己的界面 / 工具页 | 插件 |
| 我已经有别的 AI CLI 在用 | 外部执行器 |
| 让它能开浏览器点页面 | 技能包（浏览器操作） |

- [ ] 你装过一个插件，看清楚了它申请的权限
