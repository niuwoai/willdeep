# 第 16 章 上下文、成本与性能

用久了你会遇到三个问题：它怎么越来越贵、它怎么把前面说过的忘了、它怎么越跑越慢。这三件事是同一件事的三个面——上下文。

## 16.1 读懂那个圆环

状态栏右下角有个小圆环加一个百分比，鼠标悬停上去会告诉你：

> 已用约 X / Y · 其中对话约 A、系统 + 工具约 B · 剩余 C（估算）

三点说明：

- **分母是估的**。模型的上下文窗口靠模型名匹配一张表得出，不是每家都上报真值。实测有些模型的实际窗口比表里大得多。所以这个百分比是量级参考，不是精确刻度。
- **"系统 + 工具"那部分你以为很小，其实不小**。系统提示、工具定义、已挂载的技能都算在里面，几十个工具的定义能占掉可观的一块。
- 颜色会变：超过 75% 变橙，超过 90% 变红。

## 16.2 压缩：手动和自动

**手动压缩**：环旁边会出现"压缩"按钮，条件是已用超过 50% 且消息超过 6 条。点它，或者用 `/compress`。作用是把较早的对话摘要成一条，腾出空间。

**自动压缩**：到 **75%** 会自动触发，界面显示"正在自动压缩上下文"。它只在两轮之间跑，绝不打断正在流式输出的回复。

两个数不一样，别记混：**按钮出现在 50%，自动触发在 75%**。

压缩会损失细节，这是它的本质。系统做了一件事来兜底：压缩时会生成一份**检查点**，把不能丢的东西固定下来——你的原始输入、目标与验收清单、预算、最近 32 条工具回执（调用 ID、工具名、状态、退出码）。压缩期间如果任务本身变了，或者必需状态大到放不进检查点，它会放弃压缩并保留原对话，而不是硬压。

压缩之后**你在界面上仍然能看到全部历史消息**，变的只是发给模型的那一份。

**压缩模型怎么选**（设置 → AI Agents → AI 服务商 → 上下文压缩）：按窗口大小挑，不是按速度挑。窗口决定长记录被切成几块，每块都是一次独立请求。**不要用推理模型**——摘要被截断会静默丢掉会话状态，而且你不会立刻发现。

## 16.3 上下文快满时的三个选择

| 做法 | 什么时候用 | 代价 |
|---|---|---|
| 压缩后继续 | 任务还没做完，细节可以丢 | 丢细节 |
| 在新聊天中继续 | 阶段性完成，要换个话题 | 要重新建立部分上下文 |
| 重开一个会话 | 换个完全不同的任务 | 什么都不带 |

第二种在会话右键菜单里："在新聊天中继续"、"在新工作树中继续"。它会带着接力提示词开新会话，比在一个满仓会话里硬撑划算。

还有一件事：Agent 有一个"读取历史原文"的能力，可以回去读被压缩掉的原始内容，而不是靠压缩后的记忆。所以压缩后追问细节，它未必答不上来。

## 16.4 让它记住事情：四层

**第一层：规则文件（最强）**

- 仓库里的 `AGENTS.md`、`CLAUDE.md`：项目专属规则，跟着代码走。
- 「设置 → AI Agents → 规则」里的全局规则：一份小的 Markdown 索引（默认路径 `~/.willdeep/CLAUDE.md`），所有工作区生效。详细规则随 App 内置，需要时才加载。

项目内的 `AGENTS.md` / `CLAUDE.md` 更具体，优先级高于全局规则。

规则适合放"必须这样做"的硬约束：代码风格、提交流程、禁止事项。

**第二层：记忆（设置 → AI Agents → 记忆）**

默认开着，几个关键开关：

| 设置 | 默认 | 作用 |
|---|---|---|
| 启用记忆 | 开 | 总开关 |
| 自动检索记忆 | 开 | 每轮之前自动搜相关记忆注入 |
| 单次最多检索条数 | 5 | 1–20 |
| 相似度阈值 | 0.10 | 越高越严 |
| 自动归纳对话 | 开 | 从对话里抽持久事实存成候选 |
| 每日运行记忆维护 | 开（03:00） | 归档重复过期条目、清过期归档 |
| 临时记忆 TTL | 30 天 | |

记忆分全局和项目两种范围。列表里可以搜索、查看来源和使用次数、导出快照。

**第三层：会话内召回** —— 回合报告里会显示这次用到了哪些技能和记忆。

**第四层：自学习** —— 从对话里发现可复用的流程，浮现成技能候选（[第 13 章](13-extensions.md)）。

一条实用判断：**规则管"必须"，记忆管"通常"**。"提交信息必须用中文"写进规则，"这个项目的测试要用 yarn 不是 npm"放记忆里就行。

## 16.5 找回以前的对话

三种方式，覆盖面不同：

1. **⇧⌘P 搜索** —— 只搜标题。快，但你得记得标题大概叫什么。
2. **Agent 的会话搜索工具** —— 跨项目全文搜，但**每次只打开最近 40 个会话**。老会话会搜不到，而且是静默返回空，不会报错。
3. **历史回溯插件** —— 专门干这个的。提问 → 命中列表 → 看摘录 → 跳过去。它的定位是"帮你找回是哪一段对话"，不是直接替你回答。

第 2 条的限制值得记住：搜不到不等于没有。

## 16.6 钱花在哪

**Goal 模式有预算面板**（目标会话里打开），显示已报告 Token、未确认用量的预留、无法量化的请求数、当前累计上限和剩余额度。

这个面板自己写着一句免责声明，值得原样理解：**它记录的是原生主请求、带预算的 Worker 和压缩，其它辅助请求和外部 CLI 可能不在账本内。这不是整个任务的费用上限，也不是计费保证。**

额度耗尽时会暂停自动执行，并且**不会偷偷换个模型绕过计量**，也不会把未知消耗按零计算。

省钱的几条实际做法：

1. **路由用 Auto**，让便宜的模型干便宜的活。
2. **起标题和压缩配便宜模型**，别用 Pro 干这个。
3. **调查类任务派 `@scout`**，它最快最省。
4. **一个会话一个任务**，别让上下文滚成一坨。
5. **该压缩就压缩**，满仓会话的每一轮都在为前面的历史付钱。
6. **本地模型接管辅助活**（看图、起标题）。

## 16.7 让它跑得更快

- **并发上限**（设置 → AI Agents → AI 服务商）默认 3。同时开的会话多、又老是看到"正在排队，等待空闲的并发槽位"，可以调到 5 或 6。调大不会让单个任务变快，只是少排队。
- **会话自动归档**（同一页的"会话管理"）默认关。会话攒到几百个之后可以开，按项目保留最近 N 个，旧的只归档不删。置顶的、正在跑的、有草稿的会被保护。
- **别开太多面板**。终端、浏览器、网页组件、图片编辑这几个在长期不看时会自己释放资源，但开着总是要占。
- **大 Diff 别指望侧栏**。超过预算的 Diff 面板会直接拒绝渲染并告诉你去终端看，这是保护你的窗口不卡死。

## 本章检查点

- [ ] 你看得懂上下文环的提示，也知道分母是估算的
- [ ] 你知道手动压缩出现在 50%、自动压缩触发在 75%
- [ ] 你给压缩模型配了一个窗口大的非推理模型
- [ ] 你知道规则和记忆分别该放什么
- [ ] 你知道会话全文搜索只覆盖最近 40 个会话
